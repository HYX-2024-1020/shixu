# 拾序小程序、统一后端与设备同步实施计划

记录日期：2026-10-24。当前阶段：本地文字同步内核和小程序 0.1.0 原生界面骨架已实现；具体完成范围与验证结果见 [实施记录](miniprogram-implementation.md)，未勾选项仍待后续完成。

## 目标与已知条件

用户个人使用；保留 Windows 独立应用，新增微信小程序作为 iPhone 入口。手机与电脑共用资料，后续可以分别更新客户端和后端。小程序采用小程序组件，不以 web-view 嵌入现有网页交付。

已有阿里云成都 ECS：2 vCPU、2 GiB、Ubuntu 24.04、5 Mbps 峰值、按出网流量计费；依据用户截图，本轮尚未登录或核验服务器实际运行环境。用户于 2026-10-24 确认已注册小程序账号，并提供 AppID `wx03d8b4c63a26177c`。主体类型与类目权限尚未读取核实；尚无已备案域名。

本轮只在独立同步服务、小程序工程、测试、命令与相关文档中工作；并行产生的桌面改动、部署文件由其原工作保留。小程序骨架与本地同步验证不代表完整产品迁移或云端上线。

旧服务 POST /api/packets 只接收一部分投递字段；现有事项编辑、星标、AI 对话等不能依靠旧接口完整往返。旧服务删除会立即清除附件，也不能直接承接当前桌面版最近删除/恢复语义。必须先补后端，不能先把桌面数据上传到旧接口后宣称迁移成功。

## P1：统一后端与同步内核——代码实施从这里开始

先新增版本化接口与独立数据目录，不直接覆盖现有 /api 接口和个人资料。初期 SQLite 加单个处理队列即可，不引入 Redis、独立数据库服务或本机大模型。

- [ ] 建立完整工作区持久化模型：投递、稳定事项 ID、人工修改、AI 对话、原文/转写、附件、关联、用量及删除恢复状态。
- [x] 新增 /api/v2 命名空间，公开不含敏感数据的服务/协议版本信息；兼容字段与数据迁移明确分开。
- [x] 用服务端递增版本和变更游标同步，不用两台设备的本地时钟决定胜负。
- [x] 文字资料写入带唯一操作 ID；断网和重启后重放不重复创建投递。模型任务尚未接入，后续另验幂等性。
- [x] 客户端保存离线操作队列，收到服务端持久化确认后才出队；操作与资料版本在同一事务完成。
- [x] 修改携带基准版本；过期修改保留本地内容并提示冲突，可另存副本，不静默整包覆盖。
- [x] 删除/恢复有版本；永久删除标记阻止旧设备复活资料。服务 epoch 变化时停止自动上传并保留本机内容；完整重新配对界面待实现。
- [x] 草稿按设备独立保存，已提交文字资料同步，不互相覆盖输入。
- [ ] 附件独立上传、校验、确认完成后关联投递；缺失文件不能显示成已同步。成功接收后由后端继续解析与整理。
- [ ] 建立单个资料空间与可撤销设备授权。微信登录由后端验证，不相信客户端自行提交的 openid；微信端和桌面端通过有时效的配对流程绑定同一资料空间。
- [ ] 服务端保存模型密钥；小程序和桌面同步接口不返回密钥。旧桌面密钥不自动上传，服务端由用户另行配置。

第一项验收：两个独立测试客户端连接本地服务，A 新建模拟事项，B 勾选，A 能收到；随后覆盖离线修改重传、并发冲突、删除后重连、服务器重启。使用虚构数据和模拟模型，不依赖 AppID、域名或个人密钥。

## P4：云端部署与日常更新

云端部署应在 P1 本地验收完成、域名与实际发布条件清楚后进行。先检查服务器已有服务、磁盘和端口，部署隔离目录/服务；不覆盖未知现有应用。

| 更新对象         | 发布方式                                              | 数据保护                                                                                     |
| ---------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 小程序界面与功能 | 本地检查 → 开发/体验版真机验证 → 正式版提审发布       | 新版本就绪提示重启；先保存草稿并确认上传/同步状态，不在输入中强制重启                        |
| 后端与整理逻辑   | CI 检查 → 固定版本发布包 → 隔离验证 → 部署 → 健康检查 | 代码与持久数据分离；兼容旧客户端；部署前一致性备份，失败可回到已验证版本                     |
| Windows 客户端   | 新安装包覆盖升级；后续再增加签名校验的更新检查        | 本地资料目录、设备授权和离线队列保留，不要求卸载                                             |
| 数据库与协议     | 明确迁移版本、客户端能力与最低支持版本                | 新增字段优先；迁移前备份并验证恢复，破坏性迁移单独处理，旧代码不可盲目回滚到不兼容的数据结构 |

- [ ] 第一版采用手动触发、可追踪的部署；CI 通过不等于自动上线。
- [ ] 发布包含应用版本、API 版本、数据版本与提交标识；客户端显示可理解的更新状态。
- [ ] 2 GiB 服务器先串行处理文件与 AI 任务；在开发机/CI 构建，不在生产机同时运行重型构建。
- [ ] 设置一致性备份、恢复演练、日志轮转与磁盘占用检查；原件和数据库一并考虑。
- [ ] HTTPS 对外，数据库和内部应用端口不直接开放；设备凭证、微信 AppSecret、模型密钥均不进入源码或日志。

## 阶段完成标准

第一阶段交付是“有重复保护、冲突处理与删除保护的本地同步后端”，不是一个看起来像拾序但没有持久化的小程序演示。第二阶段交付才是 iPhone 真机上的完整最小流程。正式发布、云端部署、本人旧资料迁移分别记录实际结果，未验证项保留未完成状态。
