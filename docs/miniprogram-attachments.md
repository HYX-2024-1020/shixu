# 小程序原件与 v2 附件同步

关联 [Issue #17](https://github.com/HYX-2024-1020/shixu/issues/17) 与 [Draft PR #18](https://github.com/HYX-2024-1020/shixu/pull/18)。以下是 0.2.0 开发分支的代码能力，不表示云端已部署或微信已发布。

## 用户流程

桶里的“微信文件”和“图片 / 拍照”入口分别调用微信原生选择器。选择的临时文件先复制到小程序自己的持久目录，再保存索引；复制或索引保存失败时不显示为已经保存。支持只投递附件，文字可留空。草稿、索引和投递共用稳定 ID，清空草稿失败后重试不重复创建附件。

未连接时原件与投递均保存在本机；连接后明确点击“导入本机投递”才复制至服务资料空间，本机副本继续保留。远端投递先同步空附件列表，随后上传原始字节，服务器返回经过校验的描述后再持久排队关联。连接旧测试服务时原件留在本机并提示待上传，不把没有原件的文件名当作同步成功。

已保存的原件可在本次投喂、投递记录和事项详情中查看。文字原件使用本机文本预览；图片使用微信原生图片预览；Office/PDF 使用 `wx.openDocument`。这些原生入口尚未经过本轮模拟器交互或真机验收，实际格式支持仍以微信运行时为准。压缩包当前只保存、同步原件，不解包或预览。

选择器需要的隐私声明、相册/相机等授权和微信类目配置尚待实际账号验收。测试不打开选择器、不读取个人文件，也不替用户确认系统权限。

## 接口和一致性

| 接口                                                  | 行为                                                                                                                               |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `PUT /api/v2/attachments/{packetId}/{fileId}?epoch=…` | 已授权设备上传 `application/octet-stream` 原始字节；名称通过 URL 编码的 `X-Shixu-File-Name`，媒体类型通过 `X-Shixu-File-Type` 提交 |
| `GET /api/v2/attachments/{packetId}/{fileId}`         | 仅返回已关联到未删除投递的原件；强制下载、禁止 MIME 嗅探，返回 SHA256 头，不执行上传内容                                           |
| `POST /api/v2/operations`                             | 附件描述必须精确匹配已上传原件的 ID、名称、类型、长度和哈希；拒绝本机路径、虚构原件和跨投递引用                                    |

附件 ID 与投递绑定，同一 ID 的重复上传必须为同一原件。相同 SHA256 字节在 SQLite BLOB 表中去重，不修改第一次上传的内容。上传和注册引用分开，响应丢失后重放不会产生另一份原件。任何阶段失败仍保留本机字节或已持久排队的引用。下载前重新核对服务端字节长度和 SHA256，损坏时返回明确错误，不返回错误原件。

默认每份原件最多 10 MiB、每次投递最多 20 份、服务器原件总量最多 128 MiB；状态接口公开实际限制。客户端本机保存能力不代表服务器还有剩余配额，上传超限时原件仍留在本机。

删除整次投递时原件保留以便恢复；永久删除在同一 SQLite 事务中移除附件引用和无引用 BLOB。共享原件仍由其他投递引用时保留。小程序在收到永久删除确认后清理该资料空间的已登记缓存；明确保留的本机副本继续保留。移出草稿或索引写入失败留下的孤立字节暂时保留供恢复，不做未经核验的目录扫描清理。

SQLite 在线备份同时覆盖投递、设备、任务和 BLOB 原件；恢复回归核对实际二进制内容。部署环境变量、模型密钥、微信发布配置和其他机器上的本机资料不在这份数据库备份中。

## 读取与模型边界

UTF-8 文字/代码附件可从服务端真实原件读取，单份最多 60,000 字且原字节不超过 400,000。空白、NUL、非 UTF-8 或超限内容明确标为未读取。读取覆盖沿用桌面的 `Coverage` 字段，来源文本由服务端字节生成，不信任客户端伪造的同名附件文本。

图片、PDF、Office、ZIP/RAR/7z 的服务端读取仍未接入。存在这些未读取原件或尚未关联的上传时，整理/事项 AI 对话拒绝启动，不调用模型并假装已理解附件。可先手动记录事项并保留原件，不能将“微信能打开 PDF”视作“AI 已读取 PDF”。真实模型默认关闭，本轮未调用付费模型。

## 验证与回退

`npm run test:sync` 包括临时 SQLite/真实本机 HTTP 的上传、下载、重试、鉴权、跨投递隔离、容量、删除恢复、去重、哈希损坏、在线备份恢复和模型读取边界；小程序的文件系统及原生界面 API 使用合成替身。官方离线 WXML/WXSS 编译通过不等于微信选择器、下载、权限或真机通过。

2026-10-24 用户开启服务端口后，开发工程已实际打开，官方自动化接口已连通并读取到 `pages/index/index`。用户随后要求游戏期间不操作电脑，因此未继续交互、相机/相册授权、真机或上传发布操作；之后只修改后台代码和运行无窗口测试。自动化 SDK 留在独立工具目录，未添加到应用依赖。

旧的只支持文字的服务不能处理已包含附件的资料。启用新包前先做独立固定包与备份恢复验收；若要回退，不要直接把旧代码指向已使用新附件能力的数据库。应停止任务、保留一致性备份，按对应版本核对整个数据库、同步 epoch 与设备状态后再恢复。云端旧快照尚未升级，本任务未迁移个人资料。
