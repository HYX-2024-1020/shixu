# 跨块语义合并与真实事项对话质量

2026-10-31，#73/#69，Draft PR #74。只完成本增量的开发验证；B/C/D 尚有实施缺口，独立整体验收另行执行。

## 实现

事项对话新增真实模型合成样本验证。语义合并在全部读取块完成后进入同一 ReadingTasks 调度、账号槽、钱包、预留、根累计、24 调用检查点与停止/关闭屏障。每步最多一次模型调用，随后让出调度；未知费用不重发。供应商没有 merge 能力时明确提示未做跨块语义核对。

合并模型只能返回现有事项 ID 的 same/related 边，不能生成事实、引用、日期或新事项。服务端保留首项卡片标题及摘要，事实/建议/不确定性/来源取完整有序去重并集，其他不同摘要作为“补充摘要”保留。日期或类型冲突禁止合并，传递合并也再次检查；部分收下遇到语义冲突则保留所有原事项并明确核对未完成。相关关系采用双端现有 association 渲染入口，只在本次投递内建立，不声称跨历史投递的关联 AI 已共账。

所有有界事项块两两比较，包含同块比较；每块至多16项/56000字节，一次最多32项，不静默截断。该算法比较批数随事项块数平方增长；大投递仍受累计预算/活跃时间门禁保护，不能据此宣称容量性能达标或任意规模稳定内存。40项固定样本6批，远隔首尾的重复项识别与全部要求保留通过。

合并意图在独立账本绑定全部上游复用依赖键、结果 hash、模型与提示词版本。读取付费块新增不可改删 hash 凭据；合并结果也有独立凭据。旧租户结果被改、丢失或少了上游块时失败关闭，不能重新付费猜测；结果信封可恢复租户写入失败。跨修订复用只有全部上游依赖一致才成立，不是按标题猜测的缓存。旧版本已付费块没有新独立凭据且信封已清除时保持安全核对，不从可修改的租户证书自动补签；正式迁移/可信历史核对仍待实施。

Windows 与小程序共同显示“语义核对”、已完成批数及共用累计费用。原件同 hash/期限/墓碑门禁仍先执行，合并输入仅为少量已保存结果，不保存或重新构造全文。
