## 实际接线

独立实例显式 `reading.credentials=true` 才执行账号结构升级；默认生产 CLI 没有这个开关。新增一次性邀请码注册、账号密码登录、旧设备签名/微信凭证 claim、同微信身份重装恢复、设备列表、明确选择替换/撤销及改密撤销全部设备。Windows 主进程和小程序原生设置均有入口，设备名称、平台、槽位和活跃时间可见。

注册复用邀请预建的 accountId；未使用的20条邀请不算20个已注册账号。实际已注册/历史绑定/历史usage账号合计10人后拒绝新注册，保留现有用户，不因停用或删掉一个客户端重新赠额。新账号登记持久 grant intent，再由独立账本幂等发累计20元；网络丢回执和服务重启可核对继续。旧账号 claim 保留账号、bindingId、资料、epoch/队列和旧usage，不登记新grant，消费无法核实仍显示 RECONCILIATION_REQUIRED 并关闭AI；同步和手动记录可用。

用户名 trim、仅ASCII英文字母小写化、3–20码点；密码8–128码点、最多1024 UTF-8字节。使用 Node 内置异步 scrypt，N=131072/r=8/p=1、32字节独立盐、64字节散列，保存算法/参数版本；没有明文或可逆密码。依据 [Node24 scrypt](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) 与 A 已确认的参数。每实例同时最多一份密码计算，繁忙明确429，不把查询放进密码队列。存在/不存在用户名都运行同参数派生；错误不区分账号是否存在。

账号/IP滑动60秒各最多5次，连续10次失败锁15分钟，锁中尝试不延长截止时间；公共入口另在调用微信服务之前限制网络请求。计数和锁更新使用SQLite写事务。Windows继续Ed25519签名，并为公共登录保存防重放nonce；微信只接收一次性code，由服务器适配器换取并核对身份，不接受客户端openid。

槽位分配、替换、撤销、改密和操作回执在注册表事务提交，Windows最多3、微信最多1，身份唯一。满槽在验证密码后才列出设备；不会自动替换。服务端保存不可修改/删除的安全事件，替换和改密记录实际撤销的bindingId。恢复同一微信绑定不新增账号或额度。Windows claim后继续复用原签名身份，之后密码登录不会额外占一个槽。

注册和登录的操作编号/Windows签名身份先持久化，密码只在本次界面/请求内存中；回执指纹使用服务器秘密HMAC，避免保存可直接离线猜测的快速密码摘要。明确撤销不远程擦除设备本地副本。改密撤销全部后必须使用新密码重新登录。双端共用额度提示，待核对/未知费用显示中文暂停原因，不把缺失额度当作零消费；认证错误也保留机器代码并提供可读说明。

## 结构与兼容边界

账号升级在一个SQLite事务中新增凭据、槽位、操作回执、审计和登录限制，并替换旧单槽索引；已有绑定原ID映射槽1。重复启动核对投影；未知结构/版本失败关闭，错误时不删除旧单槽保护。已有v4账号结构时，未显式启用相应代码的服务拒绝启动；旧激活路由返回426，不能继续用已消费邀请码增绑设备。

这是**受控实例的账号结构升级**，不是已完成的生产多库影子迁移。尚未实施生产资料迁移、旧usage到权威账本的核对导入、独立安全水位与恢复重放。注册表内的append-only事件不能独自抵御整库回滚；E的恢复屏障仍必须完成，不能据本页开放真实账号。

HTTP断开后仍等待已接受的密码计算与注册/赠额意图落盘再关v4数据库；新回归覆盖中途断开注册。默认v3保持原来的同步关闭边界。首轮回归发现异步关闭使旧备份/测试删除目录时碰到SHM消失或文件占用，已修正并通过相关旧回归，未忽略文件或跳过备份检查。
