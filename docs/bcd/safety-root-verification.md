# 根累计的独立安全水位

2026-10-29，基线a8ec275，Refs #73/#69，Draft #74。本根水位增量已实施，B/C/D仍未整体验收。

纯合成复现：一个有效付费块后停止，将租户累计时间恢复旧值0，根stats也返回0。独立账本仍有调用，但时间/检查点/核对原因主要在租户库，旧资料配新账本不能据此安全恢复。任务定向回归已先失败，见#73复现评论。

本增量只向独立ledger追加account/packet/root/task映射及根调用/活跃时间/进度/检查点水位和安全原因，不保存正文、来源引用或模型结果。事件不可更新/删除。查询旧租户若低于已记录水位，报告保守累计并锁住继续；新taskId不能为同packet建立新根。独立映射保留缺失旧task的账本调用，费用与unknown仍以调用账本为权威，不能用风险最大值阻止合法结算。

跨库不假装原子：安全事件先成功、租户事务后失败可以产生保守门禁，须审计修复，不能自动回退独立水位。独立写入失败应阻止后续模型调用。仅在现有已知元数据上建立初始水位，不声称推导迁移前丢失的时间；正式迁移与维护解除另有门禁。改密/撤销/删除等全域safety.sqlite重放仍不在本根累计增量内。

步骤独立登记后才允许读取/模型，确认排空并记录累计后追加结束凭据。拥有执行的当前进程可继续该步；重启看到无结束凭据时必须核对，即使租户恢复成queued而非running。强制关闭后的供应商调用既有unknown费用、又有无法证明结束的时间，因此继续先返回活跃时间核对；没有移除费用风险。根映射与水位读取/追加采用独立BEGIN IMMEDIATE事务，避免不同连接用旧观察覆盖较高水位。普通SQL更新/删除触发只追加拒绝；不宣称能防御拥有数据库文件权限的恶意管理员。

## 实际验证

- 缺陷先失败后修复：合成租户时间回退、缺失旧task行/改taskId、独立步骤登记写入失败、原根调用/费用保持，追加在任务回归。未知费用不因新门禁消失。
- 只追加表更新/删除拒绝、不同账号隔离、历史门禁不能靠恢复“正确数字”自行解除、已确认步骤无假unknown、新实例发现未确认步骤均通过。
- 独立子进程写完步骤凭据后SIGKILL，父进程重开ledger、无任何租户running状态仍得到ACTIVE_TIME_RECONCILIATION，Windows与Linux普通UID均通过；不是仅新建JS对象模拟进程重启。
- Windows源码Electron新专项实际上传/停止、注入合成回退、禁用继续并重载保留提示，[Electron证据](evidence/safety-root-electron.json)。小程序实际Page/Node wx适配与签名HTTP测试回退后两端累计/原因/动作一致；桌面本地禁止动作，直接签名HTTP也拒绝继续，模型仍仅1次模拟、20模拟微元，无发布。
- Linux真实broker的19页PDF、temporary过期/补传/另一端停止继续/结果一致链仍通过，核对尾页与19/19，无放松隔离，[PDF联合证据](evidence/safety-root-pdf-linux.json)。该链3935ms单次代表性测量，事务串行强化前执行；不据此宣称性能改善/P95，新事务路径另外补受影响Linux回归。

## 剩余与回滚

这只是独立ledger中的根累计水位与执行凭据，不是全域safety.sqlite、资料备份/删除/撤销重放、审计解除或正式迁移。没有对账证据就保持门禁，不能直接清表、降低时间或退款；上述缺口继续#73/#69。恢复旧版必须关闭受控AI并保留新账本，新旧租户不一致时不能让旧版绕过水位继续；前向修复优先。未部署生产、未读取私人库/原件/备份，未安装客户端或开放账号。
