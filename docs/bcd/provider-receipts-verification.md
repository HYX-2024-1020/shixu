2026-11-01，实施#73 / 总跟踪#69，PR #74保持Draft。本增量仅补调用关联与恢复底层，B/C/D仍有实施缺口，未组织最终联合验收。

## 实现

DeepSeek整理、事项对话、图像依据核对、同投递语义合并与历史关联统一复用账本：发送前原子保存准确HTTP请求体SHA256与模型别名意图，响应后独立事务保存提供方、请求hash、响应ID、模型名、创建时间、HTTP状态、成功响应字节hash及可用的规范usage/hash。新表只保存有界元数据，不存请求体、原文、完整响应或密钥。三张表禁止UPDATE/DELETE，provider-receipts组件版本1采用事务DDL、SQL checksum与实际SQLite结构校验；这不等于完成全服务多库迁移。

同一提供方响应ID首次关联一个本地调用；跨调用重复ID、请求hash冲突、同调用响应/usage矛盾或后来缺字段试图降级关联时保留观察记录、暂停AI并阻止付费结果的认证、信封/跨修订复用与发布。有效usage仍照常计费；元数据写入失败不能抹掉可结算费用。无ID/模型/创建时间的有效usage仍结算，状态标为missing；旧调用明确legacy-unrecorded，不伪造历史关联。非200取消响应体，仅保留请求hash与HTTP状态，responseHash为null，不把它当作空响应hash。

保存有效usage证据后、结算前崩溃，可恢复结算而不再调用；只有响应身份、没有usage时继续unknown及原风险。发送后网络/读取中断保留请求意图；未执行自动重发、退款、风险清零或基于HTTP状态认定未计费。最终关闭屏障之后的晚响应保持既有不再写入规则。

宿主费用核对preview提供哈希化关联摘要，受信最终证据验证回调额外获得受保护响应ID以便外部核对；终态账单proof仍须通过既有严格验证，不由客户端提供的响应ID自动解锁。公开开发报告仅给响应ID的SHA256。公共客户端只使用既有费用暂停提示，不显示提供方标识或原始响应。

依据[官方Chat Completions响应字段](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)，响应身份可以用于关联；它不是最终账单。当前官方余额接口/响应usage不能替代逐调用最终账单证明，真实账单证据源仍未完整接线。
