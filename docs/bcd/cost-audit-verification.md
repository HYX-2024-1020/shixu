# 未知调用费用的受信核对与双端接续

2026-10-29，基线930a76c，Refs #73/#69，继续同一Draft #74。下列设计于实现前记录，本批实现与分层验证补充如下；B/C/D未整体验收。

## 设计边界

本批沿用已有归档/PDF窗口及独立账本，增加未知费用的受信宿主核对。需要独立维护鉴权和服务端证据验证器，两者缺一默认关闭；普通用户HTTP不能传管理员身份、usage或“未计费”声明解锁。验证器须把证据hash、账号、callId、原调用指纹、冻结价格和账单引用绑定，返回可信usage或明确未计费结论。不接受余额变化、HTTP失败、超时或任意hash作为未计费证明。合成验证器仅验证集成契约，不代表真实DeepSeek账单核对或上线管理端。

独立ledger同一事务结算/释放unknown风险并追加不可改删审计收据；核对绑定任务generation、根安全水位和账号账本事件序号，操作编号内容冲突拒绝，不能处理在途调用。同账号维护收据参与所有任务继续动作凭据，旧待提交继续不能因费用解锁而自动消费。核对不排队、不恢复原件、不给额度、不减少已结算消费、累计调用/活跃时间/检查点，也不解除未知时间或资料回退门禁。已发但证实未计费的调用仍计入根调用累计。

可信usage只补账，不能冒充丢失的模型结果。用户刷新看到核对提示后主动继续；当前原件重新核验、有效块复用，缺失结果可能重新整理并产生新费用。临时或已删除原件仍须同hash补传，墓碑/期限/长期额度不复活。后到usage若与未计费审计相矛盾，保留实际消费并暂停账本核对，不静默丢弃费用。

范围不包括未知活跃时间/历史检查点审计、完整安全库和正式迁移，也不包含E管理网页/受保护CLI的真实会话、角色和CSRF接线。真实模型累计10元余量仍未知，本批先零计费开发。

## 实现与故障边界

新增host-only的costMaintenanceReview/reconcileCallCost，没有普通用户维护HTTP路由。maintenanceAuthorize必须明确允许reconcile-call-cost，maintenanceVerifyCost必须返回与call/账号/指纹/价格/证据hash完全匹配、带final:true及账单引用的usage或not-billed结论。异步/残缺/额外字段/他人调用/过期根或账本水位均拒绝。只在本账号没有queued/running/applying、活动controller及sent调用时核对；纯费用证据可以补账，但不能清除独立时间/安全门禁。收据、调用状态和结算同ledger事务，收据不可改删，幂等编号改内容冲突。

原根维护凭据与账号费用收据组合为继续凭据，费用收据还随wallet提供给两端新建请求；请求保存时绑定，重放不重新取值。已创建请求不因费用收据变化而重新创建，仍沿原幂等/原件核验规则；未创建的旧请求拒绝；账号其他历史根的旧继续也不能自动获准。新建请求多出的空收据字段在首次费用核对前兼容旧受控v4；核对后缺字段的较早客户端拒绝创建，需更新客户端。不是生产迁移或旧服务可安全写新库的声明。

保留费用/根累计之外，补了两项先失败复现的完整性边界：已发送调用改成released而无未计费收据时，ledger.audit必须拒绝；核对时若另有排队任务，不能释放风险使其自动启动。后到可信usage推翻未计费收据时实际结算一次并追加冲突事件/全局暂停；与已核对usage冲突时保留原结算、记录冲突并暂停。核实费用高于原预留时按实际记账并全局暂停；即使收据写失败回滚，仍保留该定价故障的全局暂停，不允许回滚重新开放他人消费。此类全局暂停解除仍需E独立维护，不在本批自动清除。

## 质量与性能证据

[Linux普通UID受保护broker证据](evidence/cost-audit-clients-linux.json)使用固定内容与ZIP头日期的ZIP：前件、19页PDF（第9页空白）、另2页PDF、未读图像和唯一尾件。在首件有效块后让第2次模拟响应丢失usage/结果，暂停后核对：可信usage链消费20→60→160模拟微元；未计费链20→20→120模拟微元。两链都保留7次累计调用，包括那次丢失结果的已发送调用；未计费不等于未执行或根计数归零。实际模型新增0次。

两端旧创建/继续请求重放均拒绝，原件已补传可读时仍不发模型；刷新新动作后才接续。逐字核对独立预期全文、顺序、尾页/尾件、包内路径、覆盖和两端结果，全文SHA-256为`649a4359ee402f20d694c90630d12ca31af1b1aea773388890baa68d6f4dd6cd`。每份PDF最终19/19及2/2，空白/视觉/图像遗漏保留。两端主动再次创建任务各复用6块，仍无新增模型调用。temporary与deleted两个原件链均不恢复下载/长期占用或墓碑。

最终两链单次耗时约11.1/11.3秒，包含第一次故障、审计、两端旧动作拒绝、补传继续和两次主动再整理；不是P95、模型耗时、容量SLO或提速声明。解析器、原生工具和隔离资源未改，沿用930a76c已核验的读取性能边界，不重复长241页压测。
