## 架构决策（2026-10-28，实现前记录）

1. 保留现有同步、账号与原件存储入口，新增读取内核与 Linux broker。现有 v3 仍关闭新增能力；不把旧的单调用/每日次数账本改名为 v4。正式接线须同时完成独立账本、兼容迁移与双端降级，避免旁路消费。
2. broker 先验证原字节 SHA-256 与长度，交付只读输入。解析器是无网络、无凭据的纯读取层，返回版本化片段、定位和未处理范围；模型识别、事项整理及发布在隔离外进行。所有格式共享同一个覆盖与分块表示，不能让格式适配器自行发模型请求。
3. 第一轮采用 Node 内置 UTF-8 解码和 CSV 状态机，无新依赖。文本范围使用 Unicode 码点半开区间，CSV 同时保留逻辑行列与原文区间；CRLF/CR 统一 LF，保留空白、空单元格、引号内换行。120000 是窗口；分块穷尽输入。窗口不能暗中剪掉一个超长单元格。
4. Linux worker 使用 systemd 瞬态单元、最小只读 RootDirectory、动态低权限身份、网络/地址族禁止、空 capabilities、无新权限、独立受限 tmpfs 及 cgroup CPU/内存/pids/墙钟限制。只读运行时不包含主服务配置、租户库或模型密钥。无法建立隔离则失败关闭；Windows 本地解析单元测试不视为隔离。
5. 先以固定合成样本验证确定性提取，再测 broker 开销；分别报告解析与隔离端到端，不能将模型模拟时间包装为真实端到端。固定结构/覆盖断言防止优化丢字。大文件保持批量让出；持久化只允许哈希、覆盖、少量已校验结果，不能存完整正文缓存。

## 首轮及后续门禁

首轮目标是 TXT/CSV 双端原件 → 隔离读取 → 任务/预算 → 发布 → 同步。随后每轮加入图片、Office、PDF、归档，并同步补停止恢复、错误与双端交互。模块实现不等于联合闭环验收。

样本：中文/emoji/组合字符、CRLF、空文本、BOM、非法 UTF-8/NUL、二进制伪装、CSV 空格/空格列/引号/内嵌换行/损坏尾部、超过120000码点和超长行。后续扩展扫描/长PDF、跨页表格、Office工作表/段落表格、归档恶意路径及混合失败。每项核对内容、顺序、结构、来源和未处理范围；不只断言非空。
