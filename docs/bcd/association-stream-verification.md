# 大历史事项内容按记录与批次读取

2026-11-01，#73/#69，PR #74保持Draft；本次改善累计历史内容的内存占用，不宣称全部历史图结构/原件已实现流式。

## 复现与实现

修改前，401个各含45000字节事实的合成旧事项（保存数据共18227125字节）在历史关联开始前报ASSOCIATION_CONTEXT_LIMIT，只有上游整理费用，未调用关联模型。原因是旧实现收集全部完整历史包、候选和批次，并对累计元数据设16MiB上限。

现在按id遍历ready/未删除记录，一次读取并规范化一条记录；已保存事项的人工标题、事实、日期、完成/删除状态与旧数字ref规则保持。常驻分组索引只留拓扑、标题、日期和状态，复用完整shared buildGroups规则；完整事项内容和引文按记录读取，模型批次每侧16项/56000字节上限保持。没有关键词/最近若干项筛选，也没有静默截断事实、引用或尾部。

所有候选先逐批预检并增量计算完整依赖摘要，才允许第一笔关联消费；摘要与旧版JSON数组字节hash完全一致，批次顺序与指纹保持version1，已有精确付费判断继续复用。每一步仍重新核对全部依赖；即使只编辑远端尾部旧事项，也暂停且不继续付费。最终决定按每个新事项仅累计最高两个选择，保持原有排序/近分异组不自动关联规则，避免保留所有批次选择数组。

没有把完整历史内容写进持久检查点、新缓存表或临时磁盘数据库。每次从原有已保存事项重新读取，保留独立意图/付费凭据、unknown、根24调用/1800秒、停止、原子发布与原件门禁。

分组拓扑索引仍限16MiB；单条保存记录在解析前限16MiB；单个事项连同组上下文仍须放入56000字节批次。过大图结构、单条记录/事项/组继续明确暂停，不能宣称无限历史或恒定全进程内存。当前投递上游语义核对、原件/大归档成员和整个图结构的真正流式仍有缺口。
