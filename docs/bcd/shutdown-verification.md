# 受控 v4 的有限关闭排空

2026-10-28，北京时间。关联 [#73](https://github.com/HYX-2024-1020/shixu/issues/73) / [#69](https://github.com/HYX-2024-1020/shixu/issues/69)，仍属 Draft #74，B/C/D 未完成。

## 行为与恢复

此前等待 HTTP 关闭事件后才取消任务，随后无限等待请求和供应商。忽略取消的身份交换或模型适配器可能阻止数据库关闭。现在受控 v4 在调用 server.close 时立即拒绝新请求、停止调度、取消在途任务；已接受的账号请求和任务共用一段等待期，默认最多30000ms，只能配置为1至30000ms。同步原件上传和普通操作直接等待其内部异步处理器，不在正文读取完成前丢失排空跟踪。默认生产v3保留既有同步关闭边界，未启用新读取或账号配置。

等待内返回的有效usage照常结算；停止后的结果仍不可发布。期限后，对本引擎在途任务的sent调用持久记unknown，只有未发送的reserved才释放。保留累计消费、有效付费块、generation屏障；随后关闭租户/注册表，迟到成功和失败均不能再访问数据库。不会把无usage或迟到丢弃当作免费，也不自动重发。主程序拥有独立账本的生命周期，必须等待service.drained后再关闭它。

正常关闭把queued任务持久改interrupted，重新启动后须明确继续；崩溃前持久queued仍按既定启动恢复调度。关闭快照只保留正在执行的任务，避免为关闭加载全部历史覆盖。没有新增长期正文存储；不承诺抹除一个不合作适配器内部仍持有的内存。

若读取器尚未返回排队时长，不能推断剩余活跃时间。任务记SHUTDOWN_TIME_UNCERTAIN，停止不能洗掉此标记，继续返回ACTIVE_TIME_RECONCILIATION。双端任务视图显示中文原因、隐藏继续入口，保留收下有效部分/清除；尚需维护者核对接口，不能以时间记零恢复AI。已到供应商阶段的任务计入已知排队时间之外的实际活跃时长，unknown费用核清前仍不能继续。

这是一段由Node事件循环执行的数据库排空期限，不是进程强杀保证。原生scrypt不能中止，超过期限后丢弃结果，不能新建账号/发额度；它仍可能短暂占用线程和内存。宿主异常、事件循环阻塞、磁盘故障和进程终止策略仍需独立部署验证。
