# 独立账号安全检查点

2026-11-02，继续 #73 / Draft #74，基线02600da。本批解决恢复旧账号库可能恢复被撤销设备或旧密码的独立权威缺口，未实现完整备份恢复或租户删除重放，不据此勾完B/C/D。

## 实际行为

显式受控 `reading-runtime` 默认接入 `AccountSafety`。账号、设备身份/撤销/到期、凭据版本、槽位、注册额度意图和账号安全事件的有序投影只计算SHA256；独立账本只存随机检查点、前一检查点、摘要、时间及提交/中止决定。不复制密码、密码校验器、公钥、设备名、登录token或响应正文。原件和事项内容不进入本机制。

账号事务先核对本地检查点及投影，再更新本地资料；提交前先在独立账本落不可变意图，本地事务同时写新检查点并以FULL同步提交，最后独立追加决定。两个库不是原子提交：

| 中断位置 | 重启处理 |
| --- | --- |
| 独立意图已存，本地事务未提交 | 仅当旧本地检查点及摘要仍匹配最新已提交权威时追加aborted |
| 本地资料及检查点已提交，独立决定未存 | 仅当新检查点和完整摘要匹配待核对意图时追加committed |
| 任一库版本或摘要不匹配、有多个悬空意图、链不连续 | 拒绝启动或认证/写入，返回安全维护错误；不采用旧密码或恢复设备 |

每个决定同时在既有 `reading_events` 追加系统身份零金额事件，绑定检查点与投影摘要，使已有数据版本账本前缀证明包含决定；不改变用户钱包、个人消费序号或费用。普通失败操作完整回滚，不把输入错误变成永久停服。独立写入失败则当前进程保持关闭，重启才能按证据核对。重复操作与last-seen更新不追加重复检查点。

SQLite触发器只允许协调事务修改已启用保护的账号权威；另一个当前模块连接及旧连接也不能绕过。schema版本为accounts-core 5、accounts-auth 3、ledger-core 6，独立ledger-account-safety 1；前版写者不能继续写。已经启用保护的库不能通过关掉注入选项绕开；服务也检查独立账本是否已有安全意图。

## 基线和边界

首次空账号环境可建立检查点，允许预建未使用邀请。已存在绑定/密码/旧usage却没有独立安全基线时，明确拒绝 `ACCOUNT_SAFETY_BASELINE_REQUIRED`，不能凭恢复来的旧账号库自行建立最新权威。真实旧账号/此前试用v4账号接入需另行受信基线核对；本批没有实现该管理导入入口，也没有执行真实迁移。

本机制检测独立权威与账号库不一致并保持关闭，**不会重放删除、恢复资料或自行解锁**。租户删除/到期、全域安全事件、账号恢复重建、可信宿主最新水位及E完整备份恢复演练仍未完成。如果资料和全部独立权威一起回滚，仍须宿主最新可信清单防护，不能声称绝对防回退。原费用unknown/累计/初始额度、3+1槽位、同微信身份重装、离线内容、任务与卡片逻辑保留。

### 改密和新增身份的合成恢复演练

`account-safety.test.mjs` 在改密前保存账号库，随后改密并撤销旧设备，注册第二个账号，保存当前账号库。保留独立账本和已发额度，停服后以旧账号库启动会关闭服务。换回与独立检查点匹配的当前账号库后，旧密码和旧设备凭据仍被拒绝，新密码和新增账号可用。重放相同注册请求返回原身份，再次执行初始发放保持钱包不变。

这条恢复路径依赖当前可信账号库。独立账本仍只存摘要和有限的撤销证据。只有旧账号快照时，改密和新增身份仍不可重建。新增身份对应的租户资料缺失及跨库恢复仍需独立验证。
