## 本次实际实现

- `createMultiUserService({reading})` 显式接入 v4 capabilities、tasks、wallet、changes/records。默认 CLI 不提供 reading 配置，现有生产服务没有启用。账号与设备仍来自签名/微信凭证，HTTP 不能选择租户。所有现存租户启动时恢复输入保护，queued 工作恢复轮转；running 中断、未知费用不自动重发。
- 同账号 Windows/微信可发现另一端创建的任务，停止、继续、收下有效部分、清除。动作编号先在客户端保存，网络丢失沿用编号；明确业务拒绝后清除待重试动作，额度恢复不会自动消费。继续使用当前操作者设备重新授权，旧设备撤销不阻止另一有效设备接续。
- 部分收下与发布/状态/动作回执在同一租户事务提交；保留读取覆盖，另记已整理/未整理范围，两端明确展示。清除任务删除复用块及信封，保留已收下事项和消费。generation 拒绝停止后的迟到内容，但有效 usage 仍结算。
- 每 24 次调用保存累计调用、已完成块数和消费检查点；无进度保持暂停，反复继续不能跳过。超过 24 次且持续有进度的长任务可完成。活跃时间扣除 broker 队列等待，单步模型时限取 240 秒与剩余累计时间的较小值。
- 大结果不再被旧 800KB 资料校验拒绝；可信发布独立于普通客户端请求上限。v4 changes 每页一个记录，超过 400KB 的记录按 65,536 UTF-16 单位分页，客户端完整拼回并核对版本后才提交游标。分页中修改/删除导致失败保留旧游标。普通修改按字段差量传输，服务端合并保留长结果。完整大结果编辑上传的分项接口仍待补，不宣称所有长资料编辑已支持。
- v4 配置时不启动旧 AI provider；旧 `/api/v3/jobs` 创建返回 426，事项对话暂不启用，避免旁路旧每日次数/固定预留。旧同步遇到部分或长结果返回明确升级错误；普通同步/下载保持可用。尚未实现的账号、原件生命周期能力不在 capabilities 中宣称可用。

## 受保护 broker

新增固定 Unix socket 服务，只接受原字节与四字段描述。应用账号不能提交 worker/probe、路径、单元属性、命令或 runtime。socket 父目录由 root 持有且普通账号不可写，socket 为 root/指定组 0660；代码、祖先目录、最小 runtime 树均拒绝普通账号可写或链接路径。只有 broker 进程执行固定 systemd 命令，应用没有 sudo/systemd-run 权限。

独立目录 `/opt/shixu-bcd-test-20261028-v4`；broker root，应用 nobody UID65534。真实隔离读取 700,018 字节、跨设备停止/继续、迟到丢弃、双端结果一致；4 次模拟模型，80 微元合成消费。停止清除短期正文后继续重新解析，因此 parserRuns=2；这不是解析缓存退化为长期全文保存。其他 UID 访问被拒，客户端 probe 参数被拒。单次总耗时约 1.92 秒，不是 P95、容量 SLO 或提速比例。

首次增强权限检查发现 Windows tar 带来 0777 目录/0666 文件，broker 拒绝启动。独立测试代码改为 root 所有目录 0755/文件 0644 后重新通过；没有放松检查。后续打包须保留受保护所有权与权限，不能直接信任解包默认值。

复现脚本 `scripts/reading-broker-linux.mjs` 要求 root 和限定的合成目录，调用 nobody 运行真实 `AccountWorkspace` 与小程序 Page 的 Node 适配器；不读生产数据库。额外 `scripts/reading-remote-session.mjs` 为受控 SSH/Electron 联调创建独立临时实例，结束必须终止该实例并清理合成目录，不是安装器或常驻生产服务。
