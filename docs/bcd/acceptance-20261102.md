## 本轮补上的实际缺口

后续安全增量见[独立账号安全检查点](account-safety-verification.md)：受控入口以独立账本检查点拒绝旧密码/已撤销设备恢复，真实子进程退出验证两库核对。完整租户删除/到期和全域重放仍未完成；固定20项进度表中的D5仍属部分实现，不增加完成项数。

1. **长结果改一项能同步。** 双端在结果超过800KB时按事项索引发送有界`resultPatch`，保留完整本地乐观视图和稳定操作编号。服务端在同一版本/任务锁/删除/幂等事务里合并；不会把整份结果、来源覆盖和其他卡片重新上传。旧服务不支持时保留队列并提示升级，不假称保存成功。变更事项数量/结构的大规模替换仍受单次请求上限保护，应分次编辑或另建投递，不放大普通请求上限。
2. **收下前可以看。** 已完成且通过依据核对的付费结果有只读分页预览，含标题、摘要、事实/步骤、日期和短引文来源定位；每页最多8项且有字节边界。不会调用模型、扣费或写入世界/DDL。未通过图像核对的内容不展示为可信成果。
3. **收下部分后能完成剩余材料。** Windows和小程序新增“完成剩余材料”，创建关联新任务，父任务保持`partial`终态。独立账本绑定接续上下文，排除已收下块；新结果追加到现有卡片，保留原ID、人工修改、完成/星标/排序、原有关系和累计费用/时间。响应丢失重放同一任务，不重复创建或重付前缀。模型/输入/审计状态变化拒绝旧意图。累计发布引文保持每附件2000字符，付费块证明不被展示裁剪改写。已部分收下的投递不能由普通重新整理静默覆盖；材料改变后另建投递，旧事项仍保留。
4. **不再只有测试注入能接通服务。** 新增显式`server/reading-runtime.mjs`及`npm run sync:reading`入口，连接现有账号、broker、供应商适配器和独立账本，只监听回环。默认配置必须明确AI开关；无有效密钥、已过验证期限的价格、无隔离socket或账本与资料目录重叠时拒绝启用。账本不能随资料树回滚；旧账号未核对时拒绝接入，不重新领取初始额度。停止会等待受控关闭并释放登记，再关独立账本。发布包带入口及完整静态依赖，原v3默认入口不自动升级或启用AI。
5. **资料用途与保存期限有明确确认。** 连接前说明云端同步；新入口要求首次AI整理/对话及主动续办前确认DeepSeek用途、30+7期限、临时模式、本机副本和备份边界，按账号/服务与说明版本记住。未确认不创建模型任务；两端说明由同一服务契约给出，不将尚未验收的备份恢复说成已经可用。

## 可审查的启动方式

本段是源码接线说明，不是安装/部署授权。准备隔离、合成环境时，由受信宿主提供绝对路径的`SYNC_V4_CONFIG`，配置字段如下：

```json
{
  "directory": "/srv/shixu-controlled/accounts",
  "ledgerPath": "/srv/shixu-billing/ledger.sqlite",
  "brokerSocket": "/run/shixu-reader/reader.sock",
  "origin": "https://sync.shixunote.top",
  "enabled": false,
  "pdfVisual": true,
  "tariff": {
    "id": "deepseek-flash-1017-20261028-peak",
    "verifiedAt": 1,
    "validUntil": 2
  }
}
```

示例价格时间是故意过期的占位，不可用它启用AI；启用前须独立核对官方价格和时段，声明的有效窗口最多24小时。旧价格快照不可改写，重新核对相同费率不会覆盖已用快照。新费率需要新版本适配，不猜测价格。密钥仍由进程环境提供，不放入JSON、仓库、命令URL或日志；普通部署配置不接受reader/provider函数或解析器命令。broker的Linux权限、固定运行时和资源约束沿原方案单独准备；入口不自动安装或提升权限。

新资料写入版本：tenant-sync 4、tenant-reading 3、ledger-core 5；接续上下文各有tenant/ledger组件1。前一版写入器和原始SQLite连接均被拒绝；不能用旧二进制回滚新库。只在合成库做过验证，真实资料迁移仍须独立授权和演练。故障先关闭新AI入口、保留费用/unknown/删除/撤销与接续证明，采用向前修复或已核对的影子迁移。
