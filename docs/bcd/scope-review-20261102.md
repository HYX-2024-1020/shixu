# 暂停后的范围与资源审视

2026-11-02。当前指令：手头改动收尾并保存远端，随后暂停；未经用户明确恢复，不继续补格式、扩架构或跑新的功能实验。本记录给出代理负责的判断，不是自动恢复开发的指令，也不改变既有正式验收契约。

## 判断

近期推进存在优先级失衡。工作从“让拾序日常流程可用”逐步滑向“让材料解析器覆盖更多变体”，缺少稳定的首版边界和停止条件。单个修复可能正确、有价值，但其优先级未必高；已投入的工作也不能成为继续追加投入的理由。

此前“剩余百分之三十”等描述没有固定分母，不再使用。测试数量、提交数量和格式数量只能作为工程证据，不能当作用户价值或整体完成度。源码、签名适配器及隔离测试通过，也不等于本机安装版、微信真机和真实整理质量已经交付。

## 应当侧重什么

以已确认的桶/世界/DDL产品方向为中心，下一次恢复应先围绕一条常见闭环：投递普通文字或常见文件→整理卡片→核对原文并修改→保存/DDL→另一端同步→失败后停止与续接。先评估现有实现是否足够，以及实际输出是否有用、操作是否清楚。

| 层次 | 处理判断 |
| --- | --- |
| 当前主流程中可复现的资料丢失、重复消费、同步/删除错误 | 优先修复和验证；保留既有预算、unknown暂停与删除/撤销门禁 |
| 普通材料读取、整理质量、来源核对、双端状态可理解 | 优先形成可体验的稳定交付边界；测试之外还需要产品流程与输出质量验证 |
| 冷门字体/表单变体、复杂Office对象、罕见压缩/色彩细节 | 默认后移；清楚报告未完整读取可以作为首版边界，不必全部攻克 |
| 尚未启用的大规模运行模式、自动最终账单接线、复杂宿主证明与运维体系 | 按实际部署规模和风险重新排期；现有保守暂停/人工核对不能擅自放松，原计划中的未完成项也不能被冒充完成 |

完整安全恢复、撤销/删除重放等在相应运行模式开放前仍要验收；尚未完成的模式可以保持关闭。首版不应以覆盖所有未来模式为前提。本次没有安装、部署、合并或开放任何模式。

## 已出现的资源浪费与风险

- **边际收益下降：**为少见材料持续增加代码、样本和兼容分支，挤占了主流程与实际整理质量验证。高级兼容工作应冻结，直到有明确场景证明其优先级。
- **重复验证：**多次PR正文更新触发CI取消、重跑；多次阶段提交附带整套昂贵验证。后续应按有用户价值的闭环合并工作批次，保持PR概述稳定，普通状态使用评论更新；必需检查仍完整执行。
- **维护负担：**更多原生解析器、平台资产、补丁、许可证和安全边界会增加升级及排错成本。已有成果保留，但后续新增依赖/解析能力需要说明它解决哪个常见问题。
- **反馈不足：**大量源码和模拟证据尚未形成用户能直接判断收益的B/C/D安装版/手机交付，容易继续在错误重点上优化。应先确定最小可用边界，再安排实际体验验收。
- **成本错觉：**本批新增真实项目模型API调用为0，不代表开发没有资源成本。代理对话、开发时间、CI、主机测试和后续维护都要计入；历史usage估算不是开发总费用。
- **审查难度：**长期累积的大Draft PR让收益、回归和回滚边界更难判断。成果已经保存，后续可以审查并拆分交付，当前不仓促合并，也不删除已有实现。

## 当前处置

代码、验证证据与未完成清单保留在任务分支和Draft PR #74；手头批次提交后停止开发。没有继续探索新边缘问题、创建自动续跑或开启后续功能批次。后续讨论应围绕哪些能力构成第一版可用产品，取代继续追逐不可靠的完成百分比。
