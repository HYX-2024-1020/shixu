## 目标与范围

让用户在使用其他软件时持续看见自己选择的未完成事项，并直接处理短期任务与长期规划。不是只显示今日待办，也不是把所有事件强行铺满桌面。专注展示和操作，不增加声音、弹窗、定时催促或回顾提醒。

第一版面向 Windows：主程序独立看板页、单个悬浮看板、多份可保存规划、事件/DDL 双选项卡、模块化布局、手动子事项和归档。专注计时、等待跟进、进展回顾为后续候选，不进入首版。小程序本轮不实施悬浮窗口；实现时评估共享数据影响并更新双端能力表，不声称双端已交付。

## 主程序入口与规划保存

- 主程序单独增加「看板」页面，用于查看、编辑和管理规划；看板手写内容与喂进桶的资料、普通事项分开。
- 每份规划有名称，自动保存内容、来源关联、子事项、完成日期、归档记录和布局。支持日常规划、考试周等多份规划。
- 启用悬浮看板时提供「继续上次」「选择已有」「新建空白」。新建不覆盖旧规划。
- 新建规划的事件页为空；DDL 页仍默认读取主程序全部 DDL。退出看板后内容保留在主程序看板页，下次继续。

## 页面与数据边界

| 页面/内容 | 来源与默认展示 | 修改与影响 |
| --- | --- | --- |
| 事件（规划）页 | 初始空白；用户从主程序选择事项加入，或手写新增 | 只展示当前规划中选入/手写的事项；模块可以进一步筛选 |
| DDL 页 | 默认读取主程序全部 DDL，加上当前规划内有日期的手写事项，明确标注来源 | 主要扫一眼日期、倒计时、逾期；不与事件页模块混排 |
| 选入事项 | 主程序既有事项的关联展示 | 编辑和完成状态与来源同步；移出规划不删除来源；删除须清楚说明范围并沿用既有恢复规则 |
| 手写事项 | 当前规划自己拥有的内容 | 不自动进入桶、普通事项或主程序普通 DDL；可设置日期，在看板 DDL 页可见；以后由用户主动转入主程序 |

同一来源事项在多个模块中展示时仍是同一件事项。移除模块仅改变布局，移出规划仅取消展示，归档保留记录，删除才走删除语义；四者不能混为同一操作。

DDL 页支持「全部、今天、未来七天、自定义范围」，逾期有明确标记。事件页是否选入某来源事项，不限制 DDL 默认全量读取。无日期的内容不虚构截止日期；已有明确/推定时间解析规则、人工覆盖和来源依据必须保留。

## 模块与操作

提供可直接用的预设布局，并允许自由调整。单个看板内模块可添加、移除、排序、折叠、调整大小和筛选；同一模块可放多份，例如工作和生活清单。

| 模块 | 首版行为与位置 |
| --- | --- |
| 待办清单 | 事件页；已选事项与看板手写事项，新增、编辑、完成、删除，按需筛选和固定 |
| 长期挂念 | 事件页；长期事项、手动子事项、下一步、完成与归档痕迹 |
| 随手记 | 事件页；先保存为可编辑/删除的草稿，可转为当前规划内事项并自动展示 |
| 截止雷达 | DDL 页；按日期展示，范围筛选，查看剩余时间与逾期状态 |

标题、日期、子事项、完成、归档和删除等常用操作在看板内完成。原文、附件和复杂详情从对应入口打开主程序详情。普通新增和修改直接保存，不调用模型、不产生模型费用；日期识别复用现有规则并允许修改。长文本仅在用户主动选择时交给拾序整理，不能自动用 AI 生成长期步骤。

## 长期事项与成就痕迹

用户希望今天从长期事项拆出一个小步骤，完成后勾选，明天仍能看见来路与去向；需要简洁时自己归档。

- 子事项手动新增、编辑、排序、勾选，可手动指定下一步；不要求一次拆完，之后继续添加。
- 完成后原位淡化加划线，仍可读，记录完成日期；支持取消完成，不立即消失或自动移动。
- 已完成内容跨日保留，不自动清理或归档；允许折叠/隐藏完成项。
- 支持单条归档和批量归档已完成子事项；归档收在该长期事项的「已归档」区域，能展开查看与恢复展示，恢复展示不抹掉完成状态和日期。
- 紧凑状态显示已完成/总步骤与下一步，展开可操作全部步骤。
- 全部现有步骤完成时只显示「当前步骤已全部完成」，保留添加入口，不弹窗催促结束。整个长期事项必须由用户主动标记完成。

## 展示、外观与生命周期

| 形态 | 用途 |
| --- | --- |
| 小条 | 最小占用；用户选择固定事项、最近截止事项或完成数量；默认固定一件事项和展开按钮，不自动轮播 |
| 窄栏 | 放在屏幕一侧，模块纵向排列，直接处理 |
| 面板 | 拉大后展示多个模块与更多内容 |

三种形态共用规划与布局配置，切换、拉伸后不丢设置。支持拖动、拉伸、折叠、置顶/取消置顶、隐藏/恢复、快捷键显示/隐藏及锁定布局。默认紧凑清单，可主动缩成小条；不因鼠标移开而自动收起、不自动弹出抢焦点。

首版是一块看板内部多个模块，不做多个独立悬浮小窗。沿用纸黄、描边、硬阴影和现有卡片风格，背景透明度可调而文字保持清楚，提供紧凑/舒适密度，拖动和缩放时可预览布局。

主程序关闭到托盘后看板继续可用，明确退出拾序才一起退出；提供启动拾序时恢复看板选项并记住位置和布局。看板自身退出/隐藏不删除规划。

用户明确希望 Apple Music 像参考截图那样全屏时仍能看到看板：这是待验证的置顶场景，不承诺覆盖所有独占全屏或系统界面。后续核对官方平台能力并以 Windows 实测记录兼容边界；本次未操作本机 UI。

## 验收场景

1. 新建规划，事件页为空，DDL 默认显示主程序全部截止事项；两个选项卡分开。
2. 选入主程序三件事项，只在事件页显示所选；完成/编辑同步，移出不删除来源。其他未选事项不因模块筛选而意外进入事件页。
3. 手写一件有日期的临时事项，重启后仍在该规划和看板 DDL；桶、普通事项与主程序普通 DDL 不新增该临时内容。
4. 手写长期事项，今天添加并完成一步，淡化划线、日期和顺序保留；次日继续添加一步，旧记录不消失；归档后可展开和恢复；父事项不自动完成。
5. 随手记草稿退出后保留，转为看板事项后不污染桶；普通操作不触发模型请求。
6. 保存命名规划 A，再新建 B，A 不丢；从主程序看板页及再次启动入口均可恢复 A。
7. 切换小条/窄栏/面板、拉伸、折叠、锁定和重启，内容及布局正确；DDL 筛选与小条自选内容有效。
8. 置顶、取消置顶、隐藏、恢复和托盘生命周期正确，不抢输入焦点；分别记录普通最大化和 Apple Music 全屏实测。
9. 移除模块、移出规划、归档、删除各自范围明确；账号隔离、来源删除/恢复、离线与多窗口更新不破坏现有安全和一致性规则。
