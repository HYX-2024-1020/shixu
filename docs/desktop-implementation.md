# Windows 实施记录

## 2026-10-23：桌面基础第一批

选用 Electron：直接复用现有 React 与整理引擎，提供 Windows 托盘、独立窗口和后续文件处理进程。Tauri 需要新增 Rust 工具链及 IPC 适配；当前输入与文件解析更适合沿用 JS。此选择不表示桌面目标已全部实现。

应用使用 `shixu://app/` 加载随包发布的资源，不启动 Vite 或 HTTP 服务。主进程限制静态资源路径、外部导航和新窗口；渲染器启用 sandbox/contextIsolation，禁用 Node 集成。协议设计参考 [Electron 官方文档](https://www.electronjs.org/docs/latest/api/protocol)。

数据暂用现有 IndexedDB，原件字节随草稿/投递存入专属 `%APPDATA%/ShixuDesktop` profile，浏览器测试资料不迁移。后续独立附件仓库、密钥系统加密、版本迁移、备份导回与引用清理仍需开发；现有“记住密钥”仍沿用网页存储，不能称为系统密钥保险库。

### 两工作区交互草图（下一批实现）

```text
拾序                  [投递桶] [整理结果]             [设置]
投递桶：文字输入 + 附件缩略图/清单 → 丢进去
        当前队列 → 持久回执：新增/更新/合并、读取覆盖、遗漏
        [查看这次结果] → 整理结果，筛选本次投递
整理结果：搜索 | 活跃/完成/最近删除 | 排序
          有内容的类别及数量 → 课程/项目折叠组 → 事项
          事项详情：原文要求 / AI 总结 / AI 建议 / 待确认
```

界面状态在切换时保留；费用放设置，用量继续记录。视觉采用暖白底、紫蓝强调与珊瑚色反馈，角色感采用简洁桶形图形，复杂鱼动画后置。

| 内容 | 路线 | 当前状态 |
| --- | --- | --- |
| TXT/MD/CSV、DOCX、文字 PDF | 复用文本提取，补逐文件覆盖记录 | 已有实现，桌面代表材料待验 |
