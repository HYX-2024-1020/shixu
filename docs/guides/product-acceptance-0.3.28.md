# 拾序0.3.28更新与第二轮验收接续

本版集中处理0.3.27源码审查和本轮实际反馈，范围为原Windows客户端、原阿里云服务与原管理台。[实际部署/安装状态](../project-continuity/acceptance-stability-20261114.md)分别记录，原生安装尚未完成时不要拿源码版本当运行版本。

## 先完成本机更新

1. 从托盘正常退出拾序，保存未完成输入；关闭窗口收托盘不等于退出。
2. 在普通Windows会话运行本机提供的0.3.28联合更新器，沿用原安装位置。无需重新注册、重建账号、清空历史资料或改执行策略。
3. 完成后从原桌面“拾序”和“拾序管理控制台”分别打开，再由代理独立只读核验物理文件、版本和原入口。

这一步不调用模型、不新增AI费用。安装确认与功能验收分开记录；不要反复安装或自行删除账本、原件、缓存来清任务。

## 接续验收时，每批只做少量操作

先用一条合成失败材料确认：桶中保留/删除/重试是否醒目；保留后可直接手动编辑，并在收到“修改已保存”回执后退出重开。手动保留和编辑不调用AI；重试可能新增调用费用。

等待整理处可停止本次整理，保留原材料、已完成内容和可信付费进度。已发出的请求可能继续结算；费用不明或安全门禁仍需核对，停止不清账本，也不会自动继续。

之后分批复验原件下载与续期、小组、AI范围与合并/撤销、旧任务主动继续，再看管理台。云端原件所属投递或附件已删除时，先说明对应状态，不假装可下载；真正永久删除事项或附件不可恢复，只在合成资料上测试。出现问题先记路径、现象、提示，避免反复付费重试。
