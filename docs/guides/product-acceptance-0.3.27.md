# 拾序0.3.27第二轮复验指南

面向原Windows客户端、原阿里云服务与原管理台；是否已部署、已安装以[本轮交付记录](../project-continuity/acceptance-round2-repair-20261113.md)为准。建议用几条合成内容体验，发现问题记下入口、动作和提示即可，不必反复提交相同付费任务。

## 更新和第一次进入

在普通Windows会话双击本轮联合更新器，完成后仍从桌面“拾序”和“拾序管理控制台”打开。无需执行脚本、修改执行策略或重新配置SSH。代理随后核对原生回执、物理文件及原入口；安装确认与功能验收分别记录。

第一次可以注册或直接登录已有账号，也可选择“先用本机手动记录”。用途和保存期限分别确认，关闭后可从设置接续，不重复注册、不自动勾选；未确认时仍可手动管理。用途说明版本3新增最后有效备份的保护说明，需要重新确认后才派发AI。

设置顶部横向切换账号、用途与期限、设备与密码、同步、云端原件、AI与用量、本机备份，每次只展示一项；窄窗口可横向滚动。世界内分别保留“整理记录”和“整理任务”，任务里可刷新并进入云端原件管理。

## 失败、原件和旧任务

1. 对失败材料，在世界中选择保留、删除或重试。保留后是可编辑、分组、完成和删除的普通卡；删除进最近删除；重试复用原材料与可信进度。三者互斥，不能先保留又从旧任务继续生成另一批卡。
2. 在云端原件点“下载到本机”，应出现原生另存窗口；保存后显示实际路径，取消时明确说明取消。打开保存的合成文件核对内容。点“续期30天”应从当前有效期限再延长30天，并更新到期时间。原件到期影响原件下载，卡片和已确认内容继续保留。
3. 全站权限恢复后，旧暂停任务仍需本人主动继续；刷新不应自动调用模型。若仍有费用不明、原件不一致或安全门禁，应显示原因，保留原任务进度，不清账本、不反复新建付费任务。

## 小组、范围和真正合并

1. 世界中建立两个空小组，给同一卡加入两组，调整同组顺序、改名，然后退出重开。空组与归属应保留；删除一个组不删卡，另一个组仍有该卡。原有模型标签可显式采纳为长期小组；已确认的组不因AI建议自动改名或移走。
2. 隐藏一个类型入口，再恢复；内容和类型不变。切换组后仍能搜索、筛选与查看卡片。
3. 选两张日期或完成状态不同的卡，预览后确认合并。世界显示一张主卡，展开能找到各子项日期、状态、要求和原件来源；原卡退出正常列表。重开后关系仍在；撤销可恢复原卡。
4. 合并后补充主卡内容再撤销，应先说明影响，让你选择保留主卡为独立卡或取消撤销；不能静默丢掉新编辑。删除/恢复主卡不应顺带复活独立删除的其他事项。
5. 卡片对话明确选择当前卡、同次投递、小组、选定卡或当前账号。单卡中要求跨卡合并时，先列目标确认范围；AI提出合并后仍要预览确认，普通文字答复不算已经合并。发送AI会产生调用费用，确认已生成的建议本身不新增模型调用。

## 管理台和保留项

原控制台图标应清晰为“序”，客户端仍为“拾”；请在日常显示缩放下查看任务栏与快捷方式。按钮应能看出处理中、禁用、危险操作和成功/失败回执。

普通材料不可读或一次任务失败留在用户任务记录，不要求管理员代重试；多人持续服务异常、费用不明与安全风险才进入管理处置。已读不等于恢复，持续故障不因服务重启被记为已恢复，历史保留。

安全释放存储先看预演：有效原件、仍被引用或在途的材料、最后有效备份受保护；候选变化或预演过期应要求重新预演。空间不足限制新上传，已有卡片查看和手动编辑继续可用。不要为复验在真实业务上盲目恢复备份或销毁资料。
