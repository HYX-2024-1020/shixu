# DDL 截止事项

关联 [Issue #25](https://github.com/HYX-2024-1020/shixu/issues/25)。2026-10-25 开发实现，尚不表示已发行的 Windows 安装器或微信客户端已更新。

桶、世界和 DDL 是三个并列入口。投递整理出的明确日期自动进入 DDL，和世界使用同一张事项卡片，不复制任务。也可以在 DDL 的“自己补充一项”中填写标题、交付要求和日期；无需模型连接。已有事项点时间可核对原文、附件，修正日期和时刻，修改留存历史。

时间窗采用 1、3、7、14、30 天，按今天、未来时间窗内、更晚分区。逾期默认收起，日期待确认和已完成是次级折叠入口。完成/捞回同步影响世界及本次投递结果；删除或永久删除的事项不会进入 DDL。相同日期按具体时刻升序，没有时刻的排在该日末尾。当天的具体时刻已过则为逾期；只有日期的在次日才算逾期，绝不补造 23:59。

## 日期与来源

- 自动整理按保存的投递者当地 `captureDate` 解析，不按服务器今天重新计算。已有卡片按其原投递日显示绝对日期；新整理结果也持久保存绝对文案。
- 标题、总结、关键要求和建议中的今天/明天/后天/明确周几改为年月日，例如 10 月 28 日投递“明天下午三点”，显示为“2026年10月29日下午三点”，截止字段为 `2026-10-29 15:00`。
- 来源文字、证据摘录、原件保持原样，只在核对区域展示原文。它们是资料，不是程序指令。
- 手动补充、编辑或事项 AI 对话里的相对日期按本轮操作的当地日期解析，保存后不随跨日漂移。修改截止字段会同步修正卡片中的旧截止日期/时刻，原文证据保持不变。
- 支持已有引擎的完整年月日、今天/明天/后天/大后天、昨天/前天/大前天、明确周几（含上周/下周）和中文时刻。“尽快”、冲突、日期范围等不明确内容保留待确认；不自动猜年份或日期区间中的截止点。
- 没有具体时刻时保存空字符串；手动编辑可清除时刻或日期。提醒/系统通知、自动安排工作时长不属于本轮功能。

## 双端实现

Windows 使用 `src/bucket/DDL.tsx`，小程序使用 `pages/index/index` 的原生模板、滑杆和详情表单。两端共用 `shared/deadlines.mjs` 的日期绝对化、截止修正、分区与排序；构建脚本将其生成到小程序共享模块。服务器整理和事项对话也由同源代码生成，不向客户端分发模型密钥。

视觉依据用户提供的 `ddl.html`，沿用项目已有字体和角色；未引入外部字体请求、演示场景切换器、硬编码当前日期和示例任务。

## 验证与发布边界

新增回归覆盖跨月、跨年、闰日、时刻未知、当天时刻逾期、日期排序、原文留存、完成撤销、重启、无效输入和与世界共享状态。浏览器含桌面/手机尺寸，Windows 使用隔离 Electron profile；小程序包含页面生命周期、同源副本校验和官方 WXML/WXSS 编译，均使用合成资料。

正式安装器发布、微信上传审核、手机真机、真实模型质量和线上服务器升级分别验收。本轮没有使用用户密钥或个人材料进行付费模型测试。旧卡片显示绝对日期不需要重发模型请求；不能把现有个人资料的真实通知当作测试数据。

回滚：通过 PR 回退本次提交并重新生成、发布两端对应版本。没有新增数据库字段；已保存的绝对日期继续兼容旧客户端，原始来源及 UUID 不变。
