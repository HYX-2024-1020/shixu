# Windows 与微信小程序共同演进

## 完成动画与习惯打卡（Issue #34）

此前仅合入源码的修复已在本机 Windows 0.3.13 覆盖安装，实际安装 exe 的勾线绘制、退场、补位和习惯重启回归通过，见 [本机交付记录](releases/windows-0.3.13.md)。小程序共享生成及官方编译通过，微信上传与真机另验。

Windows DDL 接入世界已有的勾选绘制、退场与补位动画；小程序 DDL/世界提供勾选回弹后退场，原生布局直接补位。习惯在两端均以本地自然日打卡，勾选与详情操作保留卡片，展示今日状态和去重后的累计天数，再点可撤销当天记录，跨日可继续打卡。历史误归档的习惯重新显示为活跃卡片，已有打卡日期保留，不凭归档时间补造记录。停止习惯可删除至最近删除。

浏览器回归采样真实勾选描边、退场透明度与补位位移，并覆盖习惯重启、详情撤销及跨日；小程序页面回归验证持久化、连点去重及状态一致。微信真机动画、客户端安装/上传与公开发行仍须独立验收。

合入策略：PR #23 汇总 #18/#20 与本轮交互修正，全部必需检查通过后由已获长期授权的代理自行 squash 合入；旧 PR 在确认被吸收后关闭。域名、真实模型、手机真机和安装器/微信发布各自跟踪，不再把这些发布条件当作所有已完成源码长期停留 Draft 的原因。CI 音频使用真实 MP3 解码与显式播放时钟适配器，本机保留真实媒体播放验收，两者分别记录。

## DDL 自然时间、区间与导航避让（Issue #32）

Windows 与小程序共用日期解析：无年份月日、日号、相对日/周、月底、几天后、日期/时刻区间均转换为绝对端点；推定年月说明依据，无法解析或冲突保留待确认，原文不变。区间以开始和结束完整展示，沿用结束字段排序/逾期并将正在持续的事项纳入时间窗。人工清除日期不被自动恢复。小程序滑杆以方形描边手柄和档位黄底对齐 Windows；保留原生拖动与点选档位。两端主内容均拥有预留导航及安全区的独立滚动区域，世界拖动自动滚屏和切换工作区滚动位置同步适配。本机版本 0.3.12，正式发布和真机另行验收。

## DDL 完成勾选样式

DDL 复用各端“世界”卡片的完成控件：Windows 为圆形按钮、完成后黄色底与 SVG 勾号；小程序为同一 done-button 圆形控件及 checked 状态。取消完成沿用原有逻辑，两视图共享事项状态。Windows 本机版本为 0.3.11；小程序当前工程同步更新，微信正式发布仍独立验收。

## DDL 时刻恢复与推定（Issue #29）

Windows 与小程序共用 `shared/deadline-time.mjs`：明确时刻优先，从日期依据、绑定证据、对应来源和已保存事项对话恢复；中文分钟、全角、AM/PM、夜间跨日正确解析。用户已要求不再显示未知时刻：缺失或模糊时刻按时段/当天 23:59 推定，核对区标注依据并可手动覆盖。旧卡片显示时立即恢复，不需要重发模型；人工指定时刻优先，原文保持不变。同步/服务端 AI 运行副本由同源构建生成。当前规则取代 DDL 初版“不补具体时刻”的设计。

本机更新与验证见 [0.3.10 记录](releases/windows-0.3.10.md)；云端部署和微信上传仍分别处理。

## 共用源码与更新机制

`npm run mini:build` 用固定版本 esbuild 从桌面/shared 源码生成以下运行副本；不要直接编辑生成文件：

- `src/bucket/skins.ts`、`SkinArt.tsx` → 小程序角色预设与 7 张 PNG；既有 `public/mascot.png` 复制为同源角色图。
- `src/bucket/management.ts`、`card-copy.ts`、`card-order.ts`、`shared/relations.mjs` → 小程序同源排序、摘要、可见槽位排序和分组函数。
- `shared/bucket-engine.mjs`、`src/bucket/item-chat.ts` → v2 服务端自包含整理/对话模块，不把模型密钥放进客户端。

`npm run mini:check` 重新生成到内存并逐字节核对，检查代码、图像和 SHA256 清单；Core checks 强制执行。新增产品功能必须在 PR 的“双端影响”一节说明两端适配与关联待办，并更新上表。此规则防止遗漏评估，不能自动把任意新界面转换成另一平台代码。
