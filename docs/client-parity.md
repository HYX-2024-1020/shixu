# Windows 与微信小程序共同演进

## Windows 0.3.14 本机更新（Issue #40）

Windows已从0.3.13覆盖安装至0.3.14，邀请码设置进入实际安装版，原资料保留且不自动迁入账号；打包与安装exe分别通过5套隔离回归。微信源码保持同源，官方离线编译通过，本轮未切换当前工程或上传发布。正式域名尚未就绪，AI保持关闭，公网激活与手机验收仍待完成。见[本机交付记录](releases/windows-0.3.14.md)。

## 账号服务部署与真实联调（Issue #40）

服务端补充 v3 安装器、停服跨库备份与真实API验收入口，两端继续复用已经合入的激活/同步/AI协议，旧个人资料不自动上云。服务端关闭 DeepSeek 默认思考模式，维持一次上游请求和输出限制，避免小额度只返回推理而缺少结构化答案。真实模型仅用合成资料、最多整理和对话各一次、合计预留0.50元；部署、真实微信身份和手机验收分别记录，详见 [部署记录](accounts-deployment-2026-10-25.md)。

## 邀请账号与统一 AI（Issue #40，双端接入）

Windows 和小程序开发源码均改为邀请码激活；不再提供服务器地址、模型 Key 或模型选择入口。Windows 由主进程生成并加密保存 Ed25519 私钥和凭证，渲染层禁止直接访问 HTTP/HTTPS 模型接口；小程序通过 wx.login code 由服务器验证身份，凭证留在项目存储。固定正式地址为 sync.shixunote.top，尚未完成 HTTPS/微信域名时不宣称手机正式可用。

双端按账号隔离同步队列、投递、草稿、原件缓存及 AI 任务；原本机资料保留，不自动上传。Windows 整理及事项对话使用服务端持久队列；状态区区分激活、同步、AI 开关与每日额度（UTC 零点）。未激活、撤销凭证或额度耗尽均保留本地资料，仍可记录和手动管理事项。图片、Office、PDF 等原件可保存和预览，服务端尚不能读取其内容；新回归明确拒绝模型调用，不保留旧本机 OCR/Key 路径。旧浏览器直连入口仍是独立历史模式，不等于 Windows 或微信账号客户端。

新增独立 v3 服务端继续隔离全部资料、游标、冲突、附件与任务，并提供受保护管理 CLI、额度、预算与全站并发；默认 AI 关闭、预算为零。真实本机 HTTP、Electron 隔离窗口、微信页面生命周期和官方离线编译分别验证，不以合成微信身份替代真实登录。服务器模型 Key/AppSecret 已安全配置，v3已部署；真实模型整理/对话各一次及官方SDK的真实微信code身份验证已通过，AI已恢复关闭。Windows本机0.3.14已更新；域名、公开客户端发布与真机仍待验收。协议、隐私、迁移与部署边界见 [邀请账号说明](invite-accounts.md)。

## 共用源码与更新机制

`npm run mini:build` 用固定版本 esbuild 从桌面/shared 源码生成以下运行副本；不要直接编辑生成文件：

- `src/bucket/skins.ts`、`SkinArt.tsx` → 小程序角色预设与 7 张 PNG；既有 `public/mascot.png` 复制为同源角色图。
- `src/bucket/management.ts`、`card-copy.ts`、`card-order.ts`、`shared/relations.mjs` → 小程序同源排序、摘要、可见槽位排序和分组函数。
- `shared/bucket-engine.mjs`、`src/bucket/item-chat.ts` → v2 服务端自包含整理/对话模块，不把模型密钥放进客户端。

`npm run mini:check` 重新生成到内存并逐字节核对，检查代码、图像和 SHA256 清单；Core checks 强制执行。新增产品功能必须在 PR 的“双端影响”一节说明两端适配与关联待办，并更新上表。此规则防止遗漏评估，不能自动把任意新界面转换成另一平台代码。
