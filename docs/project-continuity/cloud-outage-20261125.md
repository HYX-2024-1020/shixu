# 拾序云服务 502 与维护暂停故障复盘

2026 年 11 月 25 日，北京时间。关联 [修复 PR #140](https://github.com/HYX-2024-1020/shixu/pull/140)。

## 现象与影响

Windows 客户端显示“暂时无法连接账号服务”和 `TypeError: fetch failed`，管理台也打不开。公网能力接口和同步变更接口同时返回 HTTP 502。云端恢复连接后，管理台仍显示“维护操作未完成”和“服务维护中”，新增上传和 AI 继续暂停。

## 排查与证据

| 观察 | 能确认什么 |
| --- | --- |
| 公网两个接口均返回 502，服务器上同步和管理端口都未监听 | 故障跨越两个入口，排查重点转向共同的后端进程 |
| 服务日志反复出现 `VERIFIED_PRICE_EXPIRED`，退出位置在运行时初始化阶段 | 启动时的价格校验使进程在开放端口前退出 |
| 刷新脚本出现 `PRICE_REVIEW_REQUIRED`，官方表格指纹与已审核值不同；人工核对 Flash 单价仍与本地记录一致 | 自动校验停止续期。指纹覆盖整张表格，具体变化的 HTML 字段未确认 |
| 凌晨 04:00 的定时备份已有快照回执，任务最终错误为 `SERVICE_HEALTH_FAILED` | 失败发生在备份流程的服务健康检查环节。快照完整性需要另行验证 |

## 根因

价格刷新脚本逐字节校验官方价目表的 HTML，只有匹配才会更新 24 小时有效期。指纹变化后，旧价格校验过期。启用 AI 的云服务在启动时就要求校验有效，而账号同步和管理台后端恰好由同一进程提供。每次重启都在初始化时退出，网关因无法连接后端而返回 502。

定时备份流程还要求服务重新启动并通过健康检查。检查失败后，系统按设计保留维护暂停，保护写入和付费操作。恢复网络可达性只解决了第一层故障，维护暂停需要根据快照和健康回执单独解除。

## 修复与验收

1. 对照官方定价核实 Flash 模型和单价，更新已审核的表格指纹，保留后续变更须复核的机制。
2. 移除阻塞整个进程启动的价格时效检查。付费模型请求仍在调用前检查价格。云端基于原部署应用这两处修复。
3. 验证公网能力接口返回 200，匿名访问变更接口返回预期的 401。本机通过已安装的管理台启动器访问首页和会话接口，均返回 200。运行时专项 5 项通过，其中一项使用过期价格配置启动服务并实际请求能力接口。
4. 校验当天备份快照的文件哈希，复核服务健康后执行系统自带的恢复维护操作。执行回执为 `succeeded`，维护状态为 `paused: false`。保留了失败记录和备份，无需回滚用户资料。

## 实践结论

价格校验应约束会产生费用的操作。把它放在整个服务的启动入口，会让价格源的一次变化同时中断登录、同步和管理。验收也需要覆盖用户操作经过的每一道状态检查：公网返回 200 证明服务可达，维护暂停已解除则要看维护回执。本次未使用用户账号执行同步，也未发起付费模型调用，因此这些接口与状态证据不能替代真实账号的端到端验收。
