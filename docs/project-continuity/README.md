## 用户方向与本次修正

拾序源于大学学习、通知和任务繁多、容易遗漏的痛点。桶接住材料，世界管理事情，DDL帮助安排截止事项。保持轻量、好用、美观和流畅，AI能合理分类和命名，云端资料可靠。免费服务器用于小范围非商业分享，不构成扩张产品和架构的理由。

Windows相对舒服；用户正在使用的应急手机网页存在狐动画/声音、文字错位和适配问题；此前看到的小程序问题较少。最大痛点是手机世界折叠/密度与操作、AI分组/命名。实际入口与版本还须定位，不能先假定各端同一故障或停用当前入口。

这是修正原方向。既有解析和其他成果保留并优先复用；必要、常见材料缺口仍可按任务推进。大学生和普通人罕用的格式变体暂停扩展。未批准删改原验收契约、丢弃成果或将未完成改称完成。

## 恢复后的推进方式

本机已固定单一日常checkout，其他旧目录不再作为新任务起点；执行[工作位置/基线检查及旧修复回归](local-workspace.md)。一个任务一个分支不等于每次更换工作目录，默认在固定位置串行推进。

任务开始先写：用户问题、平台/实际入口、复用来源、范围、验收与停止条件。一个独立任务一个分支/PR，总清单只跟踪；不再将所有工作追加到#74。公共依赖明确关联，必要时建立小型前置PR，不复制其他任务未提交内容。

每批交付一个可体验结果，适用验证后请用户判断体验。新发现先记待办，仅阻塞本批或涉及资料/费用/安全才扩范围并说明。保持必需CI，不绕过门禁；PR概述稳定，避免频繁编辑触发重跑。

恢复候选是手机世界浏览/折叠、AI分组/命名、移动适配与角色体验，云端可靠性为基础保障。这是用户问题的排序依据，不是新UI方案或已启动任务。先定位入口与版本，再选择首批。

用户负责体验与取舍；代理负责盘点、定位、方案、实现、验证和维护交付清单。无需用户重写需求或跟读技术日志。明显改变方向、平台或原验收契约时给具体方案再处理，普通实现不反复问。
