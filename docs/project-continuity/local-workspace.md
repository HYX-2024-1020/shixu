# 固定开发位置与保留旧修复

2026-11-02，延续#81/#82，任务[#83](https://github.com/HYX-2024-1020/shixu/issues/83)。上轮完成了盘点与索引，未把日常操作收敛到一个checkout；本轮补齐固定入口和可执行检查，产品开发仍暂停。

## 本机只保留一个日常开发入口

固定使用工作区根下的 **shixu-governance/**。名称沿用历史，但职责现为日常开发区，不再寻找名字与任务相似的旧目录。该checkout保持已有构建环境和本地文件位置；本次没有搬迁或删除私人目录。

其他18个checkout保留原样，按工作流程仅供参考：两个有未提交工作的目录受保护；#70/#74/#47/#51对应目录保存未合并方案或成果；已合并的历史目录用于追溯。这里的“仅供参考”是代理工作约束，不是文件系统只读权限。未删除旧目录、分支、构建产物或证据，也没有声称全部旧成果已经集成。

本机登记表位于工作区根 `.codex/shixu-workspaces.json`；根AGENTS和本机接续说明指向固定入口。其他贡献者可在自己机器的checkout父目录建立同结构登记表；没有登记表时，下述工具只验证Git基线，不假装验证本机开发位置。

## 每次任务的操作顺序

1. 在固定checkout核对status、当前任务及已有PR，执行git fetch origin。存在未完成任务或未提交修改时，先收尾或保留并报告，不自动stash/reset，不切到另一个旧目录开工。默认串行开发。
2. 新任务从最新origin/main建立专用分支，在同一路径运行 `npm run workspace:check -- --start`。继续原任务、开始构建/送达前运行 `npm run workspace:check`。检查只读，不fetch、不切分支、不合并、不改文件。
3. 工具拒绝错误checkout、main/detached、不规范任务分支、缺失origin/main、未包含origin/main的旧分支、未解决冲突；--start还拒绝待处理文件。输出分支、HEAD和已核对主线SHA，用于本次工作记录。origin/main新鲜度仍依赖前一步fetch。
4. 起点通过后，先列出本次接触模块必须保留的旧行为。修复、验收与构建均在本任务目录/分支进行，不拿旧目录dist/release或版本号相同的安装包替换当前成果。
5. 适用验证、显式暂存、提交、推送、PR/CI/合并保持原流程。合入后fetch并核对树一致；固定checkout可在干净状态停留于origin/main的detached HEAD作为待命，不在此状态编辑。下个任务仍在同一路径建立新分支，不复用已合并任务分支。

工具不是强制Git钩子或操作系统权限锁，不能阻止绕过命令的任意操作；AGENTS要求代理必须执行它。完整CI仍不可跳过。长任务遇到主线新修复时先审查合并依赖并解决冲突，不把检查报错当作允许回到旧主线的理由。

## 防止“修了新的，旧的又没了”

Git祖先检查确保起点包含已合入修复，不能证明新代码没有改坏旧行为。两类检查都需要：

| 触及模块 | 保留的既有行为 | 已有验证入口（按影响选择） |
| --- | --- | --- |
| 手机世界/卡片 | 正文可滚动，折叠/详情、完成/星标独立，排序不吞点击；#79与#56/#58成果 | e2e/admin-touch.spec.ts、e2e/admin-test.spec.ts、npm run test:sync中的小程序事件回归 |
| 角色/皮肤 | 狐动作与声音同时间轴，结束回待机，换肤停止；原生小程序差异保留 | e2e/skins.spec.ts、scripts/desktop-skins-smoke.mjs、miniprogram/tests/skin-assets.test.cjs；手机实际体验另验 |
| DDL/布局 | 倒计时、明确/推定时刻、日期区间、录入日依据、人工覆盖、排序与重启保留 | e2e/ddl.spec.ts、scripts/desktop-ddl-smoke.mjs、desktop-ddl-time-smoke.mjs、共享日期/小程序回归 |
| 资料/同步 | 本地保存、账号隔离、离线队列、冲突/删除不复活、来源与附件 | npm run test:sync、npm run test:desktop及受影响Electron专项；真实部署不靠模拟宣称通过 |
| 未合并BCD | 既有隔离、任务/费用/原件/迁移成果留在#74，不能假设main已含 | 先列来源提交和依赖，另建明确整合任务，不自动合并或丢弃未验收部分 |

只读参考旧实现与“在旧目录构建交付”必须区分。确需依赖未合并成果时，在当前任务说明来源和集成方式，经过审查进入固定开发分支；不得把源文件整份覆盖回来，也不得以最新main为由遗忘用户已体验但尚未合入的能力。

这些回归入口是已有证据位置，不代表本整理任务重做了手机或产品验收。Windows、应急网页、小程序的实际入口和安装/部署来源仍分别记录。
