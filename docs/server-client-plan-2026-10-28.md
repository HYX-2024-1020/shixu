# 重要：拾序服务端与双端接入方案

更新：2026-10-28。状态：用户确认的规划基线，**尚未实现、部署或开放**。

实施总跟踪：[Issue #69](https://github.com/HYX-2024-1020/shixu/issues/69)。术语见 [GLOSSARY](../GLOSSARY.md)。后续任务先读本方案，分阶段关联 Issue 和 PR；规则变化更新本文并记录原因。方案文档合入不代表任何功能完成，不关闭实施总跟踪。

## 1. 目标与范围

双端上传原始材料 → 服务器统一读取 → DeepSeek 整理 → 保存结果 → 双端同步。本轮包含服务端与 Windows、小程序必要修改、账号设备、预算账本、管理台和运维。复用现有服务，不引入通用 Agent Harness 或本地大模型。

不包含任务2的系统性准确率优化、模型训练、备案办理、正式域名接入和公开发布。原则：正常大任务分批完成，危险、失控或预算不足时暂停；尽量自动处理，避免连续弹窗。

## 2. 附件上传与读取

| 格式 | 处理 |
| --- | --- |
| JPG / PNG / WebP | 模型图片输入 |
| TXT / CSV | 读取文字和表格 |
| DOCX | 正文、段落、表格 |
| XLSX | 工作表、表头、行列关系 |
| PDF | 提取文字；扫描页和必要图像转图片 |
| ZIP / RAR / 7z | 安全解压后读取其中支持的文件 |

- 单文件10MB，每次最多20个附件、合计20MB；核对原件实际大小、内容和完整性。
- 暂不识别 DOC / XLS、音视频、加密文件和嵌套压缩包。可依原件规则保存下载，明确标记未读取。
- 服务端解析为准，客户端解析只用于预览；文字规范化规则保持一致。
- 读取四态：`read` 完整读取、`partial` 部分读取、`unsupported` 暂不支持、`failed` 读取失败。未处理范围另列清单；接口契约须明确旧客户端降级显示方式。
- 部分失败自动整理可读部分，明确缺失和原因；完全不可读不调用模型。
- 保留文件名、PDF页码、工作表、压缩包内部路径等依据。
- 扫描PDF不设固定总页数限制，分批读取、识别、合并并去重，不静默截断。
- 文本处理窗口暂定120,000字符，更长内容继续分段，不作为整份材料拒收条件。
- 识别、整理、合并、重试均计调用和费用。每24次调用是安全检查点，不是任务总硬顶；检查累计费用、资源和新增进度，正常则继续，持续失败或无进度则暂停，不能清零计数无限重跑。

## 3. 隔离与资源配置

- 每个上传、读取、下载、任务、结果和管理操作均由服务器校验账号权限。
- 低权限解析进程不联网、不持有模型密钥，只接触本任务材料与临时目录；限制进程、CPU、内存、时间、磁盘和可访问路径。仅使用子进程不等于隔离完成。
- 不执行宏、程序、脚本，不自动访问附件外链，不采纳附件中的系统操作或越权指令。
- 阻断路径穿越、符号链接逃逸、解压炸弹等，隔离对应文件；其他安全材料继续。
- 模型输出也需结构、大小、来源校验和安全显示，不直接执行或写入无效内容。
- 阶段B开工前必须落成配置表：解压体积、条目数、压缩比、像素、每批渲染量、嵌套策略、超时、CPU/内存/进程和临时空间上限，附理由和验证方法。不能仅写“实测确定”，也不直接照搬旧稿2GB临时空间。

## 4. 任务、停止与结果发布

- 点击“丢进去”后本次投递只读。存在 `queued/running/applying` 任务时拒绝对应写入并返回409；以任务占位，不引入租约。中断恢复后解除遗留占位，不能永久锁住。
- 状态机设计包含 `cancelled`，与完成、部分完成、错误、中断、冲突、清除等状态明确区分；阶段A提交完整迁移和转换表。
- 上传完成后关闭软件、切后台、断网不取消服务器处理；未上传完由设备保留并提示继续。
- 界面沿用“丢进去”“整理”等现有文案，“喂/消化”为内部讨论用语；停止入口语义必须清楚。
- 主动停止：停止后续、尽力中断当前步骤，保留有效已完成付费块，丢弃未完成块和未发布展示草稿，解除占位并保留输入。
- 材料不变可断点继续；改变后建立新任务，只复用核对后仍有效的块。清除原件时不能借断点保存完整提取材料。旧响应不能写入已停止或新任务；已发出的调用可能仍收费。
- 故障和额度不足保留进度，可继续或放弃本轮后修改。原件已清除则重新上传核对。
- 单步骤与总执行超时分别设置，排队不计执行时间，不能将单块超时无限按块累加。安全短暂故障最多自动重试2次；费用状态未知不盲目重发。
- 中途只读预览，完成后统一进入世界/DDL；异常时可“收下已完成部分”，保存覆盖与未处理清单。已收下结果不重复生成、不因停止删除。
- 明确再投递生成独立新记录，不覆盖旧结果；意外连点和网络重试按提交编号去重，不仅按文件哈希误合并主动投递。

## 5. 并发与预算

初始重解析并行1、模型请求并行3；每账号同时1个未完成任务，全站等待最多20个。解析与模型分别限流，账号公平轮转，长任务按批让出机会；上传、查询、下载、手动管理与同步不跟AI一起排队。数值是起步配置，须验证资源容量。

- 每账号初始累计20元，不按天重置；3台电脑和1个微信身份、全部AI功能共享。
- 全站每日50元，北京时间零点重置。不设整次投递累计金额硬顶。
- 单任务同时在途预留上限2元，不是任务总消费限制；按实施时官方价格及请求约束核算配置。
- 调用前原子预留，取得有效 `usage` 后按实际tokens及版本化价格快照结算，退还差额。金额为系统估算，不冒充供应商账单。
- 无 `usage` 的失败不扣用户余额，但保留全站未知费用风险预留；确认未计费或核对后才能释放，不能超时按零无限放行。
- 用户主要显示已消费；管理台另显示预留和未知费用。余额低于3元提醒，个人余额与全站日预算不足分别提示。
- 预计超剩余额度时提示可部分处理；用户继续后仅处理可负担范围，停止后列明进度。不能靠拆新任务绕过总额度。
- 耗尽只暂停AI，基本功能保留；日预算恢复或管理员加额后，用户主动继续，不自动消费。
- 独立账本不随资料回滚，自身必须有备份、完整性和恢复保护；恢复不能退回消费，无法核对则保持AI暂停。
- 开发真实验证独立账号、合成材料、累计最多10元，不占用户余额。右上角“元”展示属于后续界面优化。

## 6. 云端原件与本地副本

- 10人内测，每账号500MB原件逻辑额度。回收站和待清理原件仍占额度；结果、日志、备份、临时空间另设容量保障。
- 配额释放、SQLite空闲页复用、数据库文件缩小分别管理，实施前确定兼容迁移、回收和监测方案，不把仅删行或仅缩库当完整容量保障。
- 正常保存30天，提前7天提醒；到期进入7天待清理缓冲，期间可续存30天，结束后清除。不自动续期；满额也可续期已有文件，因为不新增占用。
- 云端窗口提供占用、列表、状态、期限、下载、批量续期与删除。
- 本次附件总量大于剩余空间时，整次临时整理，提前显示不保存云端原件，不自动只存一部分。
- 临时模式结束或失败清除原件、完整提取正文和转图等，保留结果、少量引用与进度；继续需重新上传。临时材料不进入长期备份、日志或任务正文副本。
- 上传设备自动尝试留原件，另一端按需下载，不镜像云盘。Windows保存至应用资料目录；小程序保存至微信本地文件空间，配额和API实施前核实，不承诺永久留存。
- 不自动删用户本地原件，文件管理为可选入口。保存失败通常仅提示；只有本地与云端均不留原件时合并确认一次。云端删除不删除设备副本。

## 7. 删除、回收站与同步

- 删除云端原件与删除整次投递分开；原件删除保留事项、摘要、来源、少量引用，清理完整正文和转换缓存。
- 投递回收站7天，原件仍占额度。原件实际清理取投递永久删除与原件最终清理期限中较早者；待清理缓冲不能延长回收站。
- 单项事项最近删除沿用现有规则，实施前核对（原修订稿记为30天），明确与投递回收站、原件期限区别，不擅自混同。
- 删除正在处理的原件先确认停止对应任务。
- 同字段最后抵达服务器的修改生效，不同字段尽量合并；覆盖保留必要历史。删除优先，旧设备改动不自动复活内容。
- 任务锁定期间的离线修改保留在设备并提示未同步，不覆盖任务输入。

## 8. 账号、登录与设备

- 最多10个内测账号，保留20个邀请记录不等于开放20人。
- 邀请码一次性注册，之后失效；账号名唯一、3–20字符、去首尾空格、英文不区分大小写；密码至少8位，成熟密码哈希与独立盐，不存明文/可逆密码。
- Windows注册用邀请+账号密码+设备公钥；新电脑以账号密码绑定，不采用旧稿已有设备批准流程。保留Ed25519设备身份。
- 微信身份经服务端验证 `wx.login`；同一绑定身份重装后可恢复；不同微信不自动顶替。
- 每账号最多3台Windows+1个微信身份，共用额度与空间。满槽明确列设备名称及活跃时间，用户选择替换，不自动顶替。
- 用户可撤销设备/微信、改密并一键撤销全部设备；管理员重置与恢复有审计。撤销不能擦除已下载文件。
- 账号/IP各每分钟5次登录尝试，连续10次失败锁15分钟；具体计数与抗恶意锁定策略在安全设计中明确。错误不泄露账号是否存在。
- 密码走TLS，不入URL、日志、错误与审计正文；回环开发测试只用合成凭据。
- 旧登录用户设置账号名密码，保留资料、绑定与消费，不能借迁移重复领取额度；无人可登录由管理员核实恢复。
- 数据结构支持按设备撤销、原子槽位计数及微信唯一性，迁移不丢原有绑定。新旧接口切换与双端更新分别验收。

## 9. 管理网页

独立回环监听，不进入主服务公网路由，经SSH隧道+独立管理员登录；HttpOnly会话、来源/CSRF防护、过期、敏感操作确认。凭证不入URL/代码/日志，与普通用户完全分离。

- 总览：服务、资源、队列、费用、备份。
- 用户：累计额度、消费、预留、余额、追加额度、暂停恢复AI。
- 设备撤销协助、密码重置。
- 任务阶段、错误、重试、暂停和停止；有费用的操作明确说明。
- 存储统计、部署版本、维护和不可由网页删除的审计。
- 暂停AI保留进度；停止丢弃本轮未发布/未收下成果，付费块仍遵守有效复用及原件清理规则。不得影响他人任务。
- 无用户原文查看、私人文件下载及用户资料导出接口，不只是隐藏按钮。排障依错误码、字节数、批次、状态和耗时等元数据；需材料时由用户自愿提供。
- 敏感修改原子幂等并审计，追加额度不清消费，不等于给供应商充值。保留受保护CLI兜底。

## 10. 备份、维护与部署

- 每天北京时间04:00一致性备份；允许短暂停服，2–5分钟为目标，不保证未经测试的时长。先停新任务、保存进度，有限等待在途步骤（原稿建议最多30秒），须规定超时及服务恢复路径。
- 注册表与租户跨库一致；账本、删除/到期/撤销等安全记录另有恢复保护，资料回滚不能让其失效。
- 最近2份成功备份，每份最长7天；新备份检查成功才替换旧份。备份失败立即暂停新增上传/AI并显示维护原因；过期副本仍清理，不能无限保留最后一份。
- 不下载至维护者电脑，接受同机故障与约一天新增数据损失风险。用户告知反映实际备份期限，不沿用旧稿额外3天承诺。
- 恢复前核对安全与费用记录，重放必要删除/撤销并清理过期内容，无法可靠核对保持关闭；实际演练恢复及回退。
- 磁盘80%暂停新上传；内存、临时空间、供应商故障等自动降级，不提前删未到期原件；基本功能尽量保留。
- 不接自动通知渠道，运维每天查看管理网页，备有网页故障时的检查命令。不要把该约定误作已创建的提醒自动化。
- 升级前备份和兼容验证，不可靠则不升级；正式AI待正式链路验收完成再开放。

## 11. 告知与测试边界

首次简短说明材料会到服务器及DeepSeek、正常/缓冲保存期、备份剩余留存和下载删除方式，确认后记住；特殊情况合并提示，不声称完全本地或供应商零留存。

备案前允许服务端隔离与合成验证、源码Windows开发版经SSH隧道联调、微信开发者工具develop环境联调。实施前核对 `SHIXU_DATA_DIR`、`SHIXU_TEST_SERVICE_ORIGIN` 和小程序transport的实际入口，仅开发环境允许回环/测试路径，生产不得带绕过校验。

备案前不验收真机、体验版、Windows安装版、正式手机网络和证书链路，不开放真实用户内测账号。使用独立合成账号及10元预算内模型验证。

备案、DNS、有效HTTPS入口及微信合法域名就绪后补正式验收；HTTPS可由反向代理提供。分别记录代码合入、服务端部署、客户端更新、手机验收、正式开放，禁止混同。

## 13. 已替换规则与跟进方式

本文取代旧讨论中的：仅服务端、10附件、扫描10/20页、8次总硬顶、单次0.5/2元总限额、个人每日1元、现有设备批准新电脑、主动停止必定从头、额外3天备份留存、同机仅一份备份、维护者电脑备份和满额禁止续期等规则。

后续每个实现PR引用本文与总Issue，在对应阶段补充Issue/PR链接、检查结果、迁移风险及回滚方法。任务2另行跟踪：本轮必须确实读取材料、验证输出和依据，但不保证模型语义永远正确。
