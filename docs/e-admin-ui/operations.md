# 真实管理及运维接线

关联 #103/#104；实际交付状态见[功能表](../project-continuity/product-delivery-20261111.md)，用户步骤见[集中总体验收](../guides/product-acceptance-0.3.25.md)。

`AdminBackend` 通过独立会话后的 `/admin/v1` 路由提供账号状态、额度追加、设备撤销及临时密码重置、任务元数据/动作/累计时限、预算、存储、告警、审计和运维队列。所有写请求校验来源/CSRF及操作编号，操作意图先持久化，再调用底层幂等账号/账本/任务协调器，最后追加审计。回执丢失后重试不重复加额或撤销；错误对象/修订/代数不能被旧确认覆盖。

管理任务视图逐字段白名单，不返回原文、模型结果、文件名、来源引文或预览。暂停推进代数、尽力中止在途步骤并清理临时材料，阻止迟到结果写入；已发费用仍结算。继续仍受设备、修订、账号、费用、时间和安全链限制。累计时限延长需核对当前代数/独立水位并留依据摘要，不重置累计、不自动执行。供应商最终账单或通用异常执行证据不足的原既定安全边界仍保留，不提供“强行清零unknown”按钮。

`CloudOperations` 在独立运维库保存追加式请求、状态事件及维护记录。控制台只入队，后台最终回执决定完成状态。Linux systemd `shixu-cloud-operations.timer` 串行检查队列，按北京时间04:00生成每日幂等备份请求；首次部署补一份一致备份。执行器仅接受备份、恢复、期限清理/页回收、应用服务重启、已校验兼容发布切换和人工恢复维护权限；不接收任意命令或路径。

执行前暂停新上传/AI，再停拾序v4应用并等待其有限关闭；不停止旧v3或其他项目。离线步骤使用服务用户和独占资料租约。跨库SQLite备份包含选定账号/租户及独立账本/审计副本，逐库完整性、外键、流式哈希和完整清单验证成功后原子发布。最近两份成功备份各自最多七天；失败不先删除旧成功副本，过期仍清理。部分工作目录有五分钟期限和精确文件清单，不长期留存无状态副本。备份保留同机，不下载维护者电脑。

恢复不覆盖当前独立账本/审计，也不以旧账号库重建密码。先核对宿主保管的最新账本/累计前缀及快照哈希，保留当前可信账号库，在独立影子目录恢复租户并复用已确认的安全重放；只有全套验证通过后切换资料版本，旧epoch需完整重同步。缺失身份/正文/正向恢复证据时保持原安全拒绝，不能创建新基线冒充恢复。失败保留维护原因；基本读取尽量保留，新上传/AI保持关闭，管理员核对后可人工恢复维护权限，仍不能解除独立安全门禁。

清理沿用30+7/回收7天等现有期限；不提前删除未过期原件，不删用户本地副本。SQLite页回收与逻辑配额释放分开，首次启用增量页回收须在停写且有至少两倍额外空间时重建。旧资料/影子副本使用既有受控退役清理，不随意递归删除未知文件。

宿主最新可信前缀置于服务用户不可写的独立位置，恢复及启动核对。新账本schema写者门禁阻止旧程序忽略新预算；发布切换只接受包含当前写者能力的精确包与校验值，失败尝试回原兼容程序，绝不回滚费用/安全库或删除保护。每日备份失败、维护、执行器过期、日/月预算及原有资源/模型异常接入独立告警中心。

本地验证分别记录模拟模型与真实HTTP、Windows适配器、真实SQLite恢复、原生目录门禁和Linux执行器；它们均不等于实际安装或用户总体验收。
