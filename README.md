# 拾序 Shixu

**一个，什么都能放的桶。**

把老师的通知和附件、几句灵感、想坚持的习惯放进同一个输入框，点“丢进去”。DeepSeek 自动分类、提炼要求、关联原文件，补充可选的下一步建议。无需先选分类、建项目或填写日期表单。

## Windows 桌面版 0.3.3

Windows x64 安装包输出到 `release/拾序 Setup 0.3.3.exe`，已发布版本见 [Releases](https://github.com/HYX-2024-1020/shixu/releases)。安装后双击“拾序”进入独立窗口；关窗进入托盘，托盘可打开或退出。普通使用无需终端、浏览器或开发服务。

0.3.3 支持每事项自由补充信息，概览聚焦简短标题与关键要求，不默认催促“待确认”。点击卡片底部“同行材料”直接预览图片、翻阅 PDF，Office/压缩包展示已提取文字；图片可放大，保存原件位于更多菜单。AI 建议采纳后就地显示“已采纳”，防止连续点击重复创建行动。

两个工作区：“桶”接收并保留文字、图片和附件草稿，点“丢进去”才整理；“世界”默认用卡片展示结果。分组是可选视图，不显示“未分组”。星标在卡片右上角，完成用圆形勾选；置顶、编辑、删除位于卡片菜单。支持搜索、状态、自定义排序、简单习惯打卡、最近删除与恢复。同次投递的文字、图片和文件留在事项详情内，不另列原件仓库。视觉以用户提供前端为基准，使用纸黄、黑色描边、硬阴影和鲸鱼角色。读取覆盖和未读原因留在回执中，补充读取的结果先确认再新增或合并，保护人工修改。

数据默认保存在 `%APPDATA%/ShixuDesktop`，原件按校验值去重保存；记住的密钥使用 Windows 系统加密，不进入备份。设置可导出和恢复包含原件、草稿、结果、最近删除及用量的备份。最近删除保留 30 天；删除事项、原始附件与整次投递的范围分别管理。

支持 DOC/DOCX、XLS/XLSX、PPT/PPTX、PDF、常见图片、代码文本、ZIP/RAR/7z。旧 PPT 可能含母版和历史文本，旧 XLS 最多读取 5000 行；Office/PDF 文本提取不等于已识别全部嵌入图表。图片和扫描页发送到 DeepSeek Flash，沿用同一密钥。真实通知图片、扫描 PDF、公开中文手写、表格/公式及分类日期边界样本已通过；有限样本不代表通用准确率。资源管理器、QQ/微信来源拖拽仍待解锁桌面后实测，详见 [产品清单](docs/desktop-product-plan.md) 和 [实施验证记录](docs/desktop-implementation.md)。

开发命令：

```powershell
npm ci
npm run desktop:start
npm run desktop:pack
```

验证：`npm test`、`npm run test:desktop`、`npm run test:desktop:ui`。UI 验证使用独立临时 profile 和模拟模型，不会读取个人资料或调用个人密钥；可用 `SHIXU_PACKAGED_EXE` 指向发布构建执行同一套测试。`SHIXU_DATA_DIR` 可指定独立的数据目录，默认不设置。

真实调用验收单独运行：`node scripts/desktop-live-check.mjs` 和 `node scripts/desktop-live-acceptance.mjs`，会使用已保存密钥并产生实际 API 用量，仅提交合成及公开样本。后者的公开手写图片来源及准备方式见 [样本说明](desktop/fixtures/README.md)；报告保存在 `release/live-validation.json` 和 `release/live-acceptance.json`。原生来源拖拽可运行 `node scripts/desktop-native-input-probe.mjs`，只接收隔离草稿，不自动提交或调用模型。

## 使用

1. 右上角“连接与设置”填写自己的 DeepSeek API 密钥。不要把密钥发到聊天、issue 或仓库里。
2. 在唯一的输入框随意输入，也可添加文件，把相关通知与附件一起投递。
3. 自动整理结果会出现在下面。展开查看原文依据、建议与原始文件；待办可直接勾选完成。

密钥默认只保留在当前页面内存。自己的设备可主动勾选“记住密钥”，保存到该浏览器；刷新后仍可自动整理。没有密钥、离线或接口失败时，原文和附件先保存在本机，绝不会用关键词规则冒充 AI。连接后待处理内容自动开始，失败内容可以重试。

示例空间使用单独数据库，预置的是明确标记的虚构结果，未调用模型。它不会读取个人记录和个人接口配置。旧版本资料没有迁移或删除，可在设置的“关于这个版本”打开旧版资料空间（`?legacy=1`）；旧版的 Supabase 配置不适用于新桶。

## 模型与费用

输入框下方直接显示当前模型和累计费用入口。设置中的“整理模型”使用下拉选择，填写密钥后可“读取可用模型”；连接前验证所选模型，模型不可用时提示重新选择，不会静默换成另一款。切换对后续投递生效，已经开始的一整包处理继续使用原模型。

每次模型请求单独保存用量记录，包括分段、合并、修复、失败或中断的尝试。记录含调用时间、模型、Token 用量和价格快照，不含密钥、提示词或原文。Token 来自 API 的 `usage`，推理 Token 已包含在输出量中，不重复计数。未取得用量的调用显示“待核对”，不会伪造零费用。删除事项保留用量记录；ZIP 备份也包含这份记录。

累计金额是人民币**估算区间**，使用 2026-10-22 核对的[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，按缓存命中/未命中分别计算，显示空闲至高峰价格范围，避免猜测法定节假日。缓存明细缺失会扩大范围，未知价格的模型只记录用量。每次调用固化当时估算，不会以后用新价格重算历史。价格可能变化，实际扣款请核对官方账单。

只能从这一版本开始统计，之前的消耗无法补齐；浏览器版只统计当前浏览器、个人服务版统计该服务，均可能包含曾使用的不同密钥。不是整个 DeepSeek 账户的历史总账。“刷新余额”读取官方 `/user/balance`，余额会受充值、赠送额度和其他应用调用影响，不能当成本站累计消费。余额只在当前设置面板显示，不持久保存。

## 自动整理怎样工作

新投递完成提炼后，会继续与已有未完成事项关联：重复的同一项工作合成一个子项，同一课程或项目的不同部分归成一组。比如昨天的 Python 第一课与今天的第二课作业，会显示为一个组，两课仍各自保留日期、要求、附件和完成状态。习惯与灵感分别关联，不跨类型合并。

这一步使用模型判断和原文引用校验，不是按共享关键词直接合并。仅发送已有事项的标题、摘要、部分要求与引用片段及相关分组摘要；所有未完成候选按大小分批考虑，不只查看最近几条。可能增加模型调用与费用，已纳入用量统计。模型的自报置信度不是经过校准的成功概率，仍可能误判；不确定、引用无效、候选冲突或调用失败时保留独立事项。已完成和已删除的事项不作为新的关联目标，关联返回后会再次检查目标状态。

组内的“要求、原文与附件”可展开查看各次投递，也可“拆开这一组”。拆开不改变原文、附件、各子项日期与完成状态；删除某次原始投递会清理依赖它的关联。关联失败后只需“仅重试关联”，不会重新分析整份文件。既有历史不会在升级后自动批量重跑，后续新投递会与当前未完成内容比较。

[查看虚构的 Python 跨天合并示例](https://hyx-2024-1020.github.io/shixu/?preview=relations)：使用另一个独立示例数据库，未调用模型。当前新增的模拟测试覆盖跨天分组、重复去重、不同日期、完成/删除竞态、拆开、源文件下载、跨重启恢复和额外调用计费；真实材料上的语义准确率尚待使用者试用验证。

- 把一次投递当作一个完整语境：通知说“按附件要求交作业”，会与附件正文共同发送给模型，提炼同一个任务。
- 自动区分待办、灵感、习惯、资料。短灵感可以得到具体的起步建议，建议明确标注，避免与老师要求混在一起。
- 每条事项必须附上能在原文中找到的引用。结构或引用不合格时自动尝试修复一次，仍失败则提示重试。
- 日期只接受可从原文明确计算的依据，例如“明天”“下周三”“2026年10月30日”。相对日期按投递时的设备日期计算。缺少年份、日期区间、“月底”等模糊说法暂时留空并说明。无上午/下午的“三点”不会猜成 03:00。
- 长内容自动分段理解，再合并去重。每一段保留来源标识，不会悄悄丢掉长文件末尾；可能产生多次模型调用和相应费用。

这些校验能限制部分错误，不能证明模型总结的语义完全正确。重要要求请通过“原文与附件”核对。当前测试覆盖模拟模型响应、引用校验与操作流程；尚未使用项目拥有者的真实密钥进行模型质量评测。

支持 TXT / MD / CSV、DOCX 正文、文字型 PDF。每次最多 8 个附件，单个 15 MB，合计 24 MB；PDF 最多 100 页，单个提取结果最多 6 万字符，整包最多 12 万字符。扫描件 OCR、旧 DOC、复杂表格版式与图片识别暂不支持。无法提取时保留原文件，整包明确显示失败。

## 手机与离线

iPhone 用 Safari 打开在线地址，点“分享 → 添加到主屏幕”；电脑可在 Edge / Chrome 安装为应用。首次完整访问后可以离线打开、保存输入，AI 需要联网。浏览器直连版的处理在页面打开时运行；关闭后未完成的投递会在下次打开并连接模型后继续。

GitHub Pages 只托管程序，当前入口的个人内容保存在各设备浏览器，**尚未开启跨设备同步**。域名、浏览器和 iOS 主屏幕 App 可能使用不同存储空间。清理网站数据会丢失本机内容，请先备份。运营商到 GitHub Pages 的连接问题仍可能影响首次访问与更新。

## 可选：个人服务

浏览器直连不需要服务器或自建 GPU，使用现有 DeepSeek API 即可。需要手机电脑共用记录、密钥留在后端、关闭页面继续处理时，可运行仓库附带的单用户 Node 服务：

```bash
npm run build
# 把 .env.example 复制为 .env，按注释填写；不要提交 .env。
npm start
```

默认仅本机监听，打开 `http://localhost:8787`。在页面配置密钥，或由服务端设置 `DEEPSEEK_API_KEY`。服务器将队列、原文、提取文字、原文件和结果保存在 `data/` 的 SQLite 数据库，处理过程中重启可恢复队列。设备通过同一个服务网址和访问口令访问，页面打开时约每 4 秒同步一次。完成状态离线修改后会补传；同时修改采用最后同步写入，暂不做协同合并。个人服务目前未部署到公网。

公网部署必须设置：

```dotenv
HOST=0.0.0.0
PORT=8787
APP_ORIGIN=https://your-own-domain.example
APP_PASSWORD=至少12位的随机个人访问口令
DATA_DIR=/persistent/path/shixu
```

需要 HTTPS 反向代理或支持 HTTPS 的托管平台，以及可持久化的磁盘。`APP_ORIGIN` 必须是实际访问的来源（无尾斜杠、无子路径）。前端与 API 从该域名根路径一起提供，不能把 GitHub Pages 直接当作这一服务的前端。公网监听缺少口令或 HTTPS 配置时拒绝启动。建议使用随机长口令，不要放在公共共用设备上。

仓库也提供 Dockerfile（未在本次环境构建 Docker 镜像）：

```bash
docker build -t shixu .
docker run -d --name shixu --restart unless-stopped -p 127.0.0.1:8787:8787 --env-file .env -e HOST=0.0.0.0 -e DATA_DIR=/data -v shixu-data:/data shixu
```

由 HTTPS 反向代理转发到 8787；`.env` 中必须有正式 `APP_ORIGIN` 与口令。保护磁盘、平台账号和环境变量；停止服务后备份整个数据目录（包括会话签名密钥）。不要只复制正在写入的 SQLite 主文件。没有替你创建付费实例或绑定域名。

## 隐私与备份

直连模式把输入文字、提取后的文件文字及跨次关联所需的已有未完成事项摘要、引用片段发送给 DeepSeek，不发送文件二进制。个人服务模式会额外把原文件上传至你自己的服务，以供其他设备取回。服务端密钥不返回浏览器。DeepSeek 对请求的处理适用其服务政策。

设置中的“备份桶里的内容”导出 ZIP，含原文、整理结果和原始附件，不含 API 密钥、接口配置或登录会话。备份为明文，请妥善保存；当前提供归档导出，尚未提供 ZIP 一键导回界面。本机数据库、可选记住的密钥与服务器数据库没有额外静态加密，也不是端到端加密同步。

无广告、分析埋点或遥测。详见 [PRIVACY.md](PRIVACY.md) 与 [SECURITY.md](SECURITY.md)。`.gitignore` / `.dockerignore` 排除了环境变量、私有运行配置、数据目录和备份；这些规则不能自动识别任意命名的个人文件，提交前仍需检查。

## 静态部署与技术

`npm run build` 产出 `dist/`，可部署至 HTTPS 静态托管。子路径构建设置 `VITE_BASE_PATH`，例如 GitHub Pages 的 `/shixu/`。工作流只上传程序构建产物。`sw.js` 与 HTML 应禁止长期缓存，哈希资源可长期缓存，私有 API 不进入离线缓存。

React + TypeScript + Vite；IndexedDB 保存本机投递和草稿；PDF.js / fflate 提取文件；共享的整理引擎在浏览器或 Node 服务使用同一套引用和日期校验；Node 内置 SQLite 提供可选个人后端。保留旧版源码用于访问既有资料，新版不依赖旧版的分类规则。

## iPhone 与 iPad

用 Safari 打开正式地址 https://hyx-2024-1020.github.io/shixu/ ，在分享菜单中选择“添加到主屏幕”；若出现“作为网页 App 打开”，开启后添加。页面底部也有折叠安装指南。主屏幕启动时使用独立窗口，安装指南自动隐藏。

适配触屏按钮、刘海和底部安全区、iPad 横竖屏及窄窗口；输入字号至少 16px，触屏首页不自动聚焦输入。点“放个文件”选择系统“文件”中的 TXT、MD、CSV、DOCX、文字型 PDF。微信等应用中的附件可先存到“文件”。iOS 分享菜单直接投递文件尚未实现。

当前公开版本的数据仍保存在设备本地，添加到主屏幕不代表启用云同步。建议固定使用主屏幕入口，在设置中定期导出备份。首次加载及 AI 整理需要联网；已加载的页面支持离线接收输入，恢复联网并保持前台后再整理。iOS 可能暂停后台页面，不能保证锁屏后继续处理。

自动化检查包含 Playwright WebKit 的 iPhone 和 iPad 横竖屏、窄窗口、文件持久化与勾选操作；它不是 iOS 真机测试，系统键盘、系统文件选择器和实际主屏幕安装仍需真机验证。
